# UserMain 종목별 전적 칼럼

2026-10-06: 클라이언트 모델과 생성·조회·수정 요청에 다음 정수 칼럼을 추가했다.

| 칼럼 | 의미 | 신규 기본값 |
|---|---|---|
| Ball_4_Win | 4구 승리 | 0 |
| Ball_4_Lose | 4구 패배 | 0 |
| Ball_4_Draw | 4구 무승부 | 0 |
| Ball_3_Win | 3구 승리 | 0 |
| Ball_3_Lose | 3구 패배 | 0 |
| Ball_3_Draw | 3구 무승부 | 0 |

- 기존 Win/Lose는 종목을 분류할 수 없는 과거 전적으로 유지한다. 신규 칼럼으로 자동 배분하지 않는다.
- 기존 행에 새 칼럼이 없으면 본인 및 상대 조회에서 0으로 읽는다. 조회 자체는 서버 데이터를 수정하지 않는다.
- 신규 Insert 또는 기존 UserMainDataUpdate 요청 성공 시 새 칼럼이 저장된다.
- 뒤끝 콘솔에서 UserMain의 public·스키마 미정의·활성 설정을 확인했다. 2026-10-06 기존 데이터 2행에 위 6개 칼럼을 number 타입, 값 0으로 추가하고 서버 재조회로 확인했다. 기존 Win/Lose와 재화 등 다른 값은 보존했다. 이전 이름의 종목별 칼럼은 없었다. 신규 행은 클라이언트 Insert 요청으로 같은 칼럼을 생성한다.
- 경기 종료 시 전적 증가, 서버 정산, UI 표시와 기존 사용자 전체 일괄 이전은 이번 변경에 포함하지 않았다.
- UserMainDataUpdate는 기존의 전체 상태 저장 방식이다. 서버 정산을 도입할 때는 종목별 전적과 재화를 클라이언트 전체 저장에서 분리해 오래된 값으로 덮어쓰지 않도록 해야 한다.
- 승률은 승리 / (승리 + 패배 + 무승부)로 계산하고 경기 수가 0인 경우 별도 표시한다. 승률 칼럼은 저장하지 않는다.

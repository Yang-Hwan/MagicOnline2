## 2단계: 매칭 안정화 — 로컬 검증 통과, 서버 통합검증 대기

- 로컬 rooms 목록으로 방 생성/참가를 결정하던 방식을 Photon JoinRandomOrCreateRoom으로 변경했다.
- 서버가 HallIdx, 경기 규칙 키, 프로토콜이 같은 2인 방을 찾는다. 규칙 키에는 종목·목표점수·쿠션·시간·마무리·입장금액 범위가 포함된다.
- Photon GameVersion에 `pavilion-match-2`를 추가한다. **양쪽 모두 새 빌드로 다시 시작해야 한다. 이전 빌드와는 매칭되지 않는다.** 아직 경기 실행은 기존 Pavilion이다.
- 같은 요청의 중복 전송을 막고, 입장 요청이 20초 안에 끝나지 않으면 실패 처리 후 연결을 정리한다. 이 시간은 상대를 기다리는 시간 제한이 아니라 방 입장 요청의 제한시간이다.
- 입장 중 나가기를 누르면 요청을 취소하고, 늦은 방 입장 콜백은 경기 시작으로 이어지지 않도록 처리했다.
- 대기실을 먼저 활성화하여 동기적인 요청 실패 이벤트도 받을 수 있게 했다. 입장 중/상대 대기/입장 실패/연결 끊김 상태를 표시한다.
- 두 대기실의 중복 카운트다운과 비활성화 시 취소, 취소 토큰 수명을 보완했다.
- 방 목록 갱신은 객체 참조 대신 방 이름으로 교체한다. 형식이 잘못된 방 이름은 무시한다.
- 퇴장 후 RemoveRPCs 호출을 제거하고 방 안에서 정리하도록 옮겼다.

검증: Unity 컴파일 성공. 2026-09-23 최종 PracticeIntegrationValidation은 completed=true, passed=true, errors=[]이다. 설정 주입 검사 2회, 매칭 호환 키 검사 2회, 연습 3구·4구·결과 복귀·리플레이 19슬롯·드래그·EggBox·네트워크 종료 정리가 통과했다. 최초 실행은 재컴파일 대기 때문에 시작 단계 제한시간을 넘겼으며, 컴파일 완료 후 새 실행으로 통과했다.

실제 Photon 서버 동시 매칭, 네트워크 타임아웃, 양쪽 경기 시작은 별도 두 클라이언트 검증이 필요하다. 자동 재시도와 통합 세션 상태 머신은 아직 도입하지 않았으며 실패 시 뒤로 가서 다시 입장한다. 대전 경기장 자체는 여전히 Pavilion이며, TableSet07 대전 전환은 다음 단계의 세션/어댑터·씬 준비 및 샷 동기화 작업이다.

## 3단계: 새 경기장 준비 세션과 전송 경로

2026-09-23 적용 내용:

- MatchStartSession은 Configuring → Loading → Ready → Started 상태를 관리한다. 양쪽 설정 확인 전에는 로딩할 수 없고, 양쪽 SceneReady 전에는 시작할 수 없다.
- 참가자 Actor, matchId, 설정 키를 검사한다. 중복 확인은 한 명으로만 세며, 이전 경기·외부 Actor·다른 설정·손님의 시작 승인·중복 시작을 거절한다.
- 준비 제한시간 30초, 참가자 이탈, 방장 변경, 접속 종료 시 준비 세션을 중단한다.
- PracticeMatchSetupTransport를 Network 객체에 연결했다. Photon 신뢰 이벤트 150~155로 설정 제안·확인·로딩·준비·시작·취소를 전달한다. 발신자는 메시지 본문이 아니라 Photon EventData.Sender로 검사한다.
- 방장은 선택한 경기장 설정과 참가자 좌석을 제안하고, 상대는 자신의 경기장 차트와 대조한다. 중복 로딩 메시지로 씬을 다시 여는 것을 방지한다.
- PracticeSceneFlow.EnterOnline(session)과 PracticeMatchAdapter가 TableSet07의 온라인 설정 및 로딩 완료를 연결한다. BallC/ShotCtrl/UI 초기화 후 로컬 준비를 알린다.
- 온라인 준비 중에는 임의 초구 뿌리기·물리 진행·샷·로컬 턴 타이머를 차단한다. 승리 후 연습 메뉴 자동 복귀와도 분리한다.
- 온라인 경로에서 나가면 세션을 중단하고 대전 메뉴 방향으로 복귀한다. 이어서 연습에 들어가면 연습 설정을 새로 구성한다.

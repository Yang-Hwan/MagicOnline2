# 대전 시간 종료 동기화 (2026-10-28)

최근 경기 `965f7c48463b4d6f9750703e8d5a6b71`은 A가 3:2/승리,
B가 3:3/무승부를 보고했다. 서버는 불일치로 정산을 보류했다.
클라이언트에는 각자 시작하는 UTC 타이머와 서버 확인 전 결과 표시 경로가 남아 있었다.

## 변경

- 최초 호스트가 공 뿌리기 완료 후 Photon 공통 시각으로 종료 시각을 정한다.
- 호스트가 종료 준비 신호를 보내면 양쪽은 새 샷과 이닝 타이머 진행을 막는다.
- 이미 시작한 스트로크, 공 이동, 지연된 득점 판정은 끝까지 처리한다.
- 각자 처리가 끝나면 준비 완료를 보낸다. 호스트는 양쪽 준비 완료와 자신의 공 정지를 확인한 후 종료를 확정한다.
- 샷/준비/종료 RPC는 같은 reliable 채널을 사용한다. 수신 측도 종료 신호 후 자신의 진행 중 샷 처리를 기다린다.
- RPC는 경기 ID와 발신자 역할을 확인한다. 재대결 시 종료 상태와 시각을 초기화한다.
- 결과를 먼저 서버에 보고하고 서버 영수증의 승자를 표시한다. 불일치 상태에서는 양쪽 모두 `경기 결과 확인 필요`를 표시하며 점수를 임의로 덮어쓰거나 정산하지 않는다.
- 프로토콜에 `timeout2`를 추가했다. 이전 버전 클라이언트와 같은 방에 들어가지 않는다.

## 검증

- Unity C# 컴파일 통과.
- 임시 DB 스키마의 서버 회귀 검사 15개 통과. 3:2 승리/3:3 무승부 충돌, 동일 무승부 정산, 분쟁 후 재입장 예약 해제를 포함한다. 실제 회원의 지갑과 경기 결과는 변경하지 않았다.
- 별도 Windows 빌드: `Builds/TimeoutRecovery/MagicOnline2.exe`.
- 실제 두 클라이언트의 네트워크 지연을 포함한 플레이 테스트는 아직 수행하지 않았다.

## 두 클라이언트 확인 항목

양쪽 모두 같은 새 빌드 폴더를 사용한다. exe 하나만 복사하지 말고 폴더 전체를 복사한다.

1. 샷 없이 시간 종료: 양쪽 무승부, 서버 정산 일치.
2. 시간 종료 직전에 스트로크 시작: 양쪽 모두 해당 샷과 득점 판정 완료 후 종료.
3. 시간 종료 직전에 마지막 득점 또는 파울: 양쪽 점수와 승자 일치.
4. 같은 상대와 재대결 반복: 매 경기 타이머 초기화와 재입장 확인.
5. 종료 확인 중 연결 끊김: 기존 서버 연결 종료 정책으로 처리되며 로컬 승패를 미리 표시하지 않는지 확인.

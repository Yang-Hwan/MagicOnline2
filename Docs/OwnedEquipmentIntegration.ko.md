# 보유장비 조회와 장착 선택

작성일: 2026-11-12

## 메뉴 동작

메인 메뉴의 `보유장비`에서 구매한 큐대·캐릭터·메시지 묶음을 조회한다. 종류별 탭, 세 상품 단위 페이지 이동, 상품 정보, 장착 상태와 새로고침을 제공한다.

- 큐대와 캐릭터는 각각 하나만 장착한다. 다른 상품을 장착하면 해당 종류의 기존 선택을 교체한다.
- 메시지 묶음은 여러 개를 함께 선택할 수 있다.
- 장착 중인 상품에는 `장착 해제` 버튼을 표시한다. 해제하면 해당 선택을 비운다.
- 구매한 상품은 판매 중지, 판매 기간 종료 또는 비공개 상태여도 보유장비에서 조회·선택할 수 있다.
- 장착 선택은 DB에 저장되므로 로그아웃·재로그인 후에도 유지된다.
- 장착·해제는 보석을 차감하지 않는다.

이 문서는 보유장비 메뉴의 조회와 장착 선택 저장을 설명한다. 후속 구현인 실제 경기의 큐대 성능·캐릭터 감정 이미지·선택 메시지 적용은 [경기 반영 문서](MatchEquipmentGameplay.ko.md)를 참고한다. 리소스 경로에 실제 이미지가 없으면 대체 문구를 표시한다.

## API와 저장 구조

### GET /api/me/inventory

게임 계정 인증이 필요하며 `Products` 배열을 반환한다. 상품 상세 필드는 상점 조회 계약을 재사용한다.

- 요청자의 `shop_user_inventory`에 있는 상품만 반환한다.
- 공개 여부 및 판매 기간으로 필터링하지 않는다.
- `Owned`는 보유 여부, `Equipped`는 요청자의 현재 선택 여부다.
- 큐대·캐릭터는 `shop_user_equipment`, 메시지는 `shop_user_selected_message_packs`에서 선택 여부를 읽는다.
- 상점 조회 API에도 `Equipped`를 추가했다.
- 하나의 SQL 문으로 상품 상세와 선택 상태를 조회한다.

### POST /api/me/equipment

```json
{
  "Slot": "Cue",
  "ProductId": 8,
  "Equipped": true
}
```

Slot은 Cue / Character / MessagePack 중 하나다. Equipped=false는 해당 상품의 선택 해제를 뜻한다. 사용자 ID는 클라이언트 입력이 아닌 인증 정보에서 가져온다.

서버는 구매와 동일한 사용자 지갑 행 잠금으로 변경을 직렬화하고, 실제 보유 여부와 상품 종류를 검사한 뒤 저장한다. 장착은 단순 토글이 아닌 명시적인 목표 상태로 처리하므로 같은 요청을 반복해도 선택이 뒤집히지 않는다. 이전 큐대를 해제하는 지연 요청이 도착해도 새 큐대는 해제하지 않는다.

실제 구매 보유 정보가 없으면 EquipmentNotOwned, 상품 종류와 슬롯이 다르면 EquipmentKindMismatch로 거부한다. 보유·구매·재화 원장은 장착 처리로 변경하지 않는다. 기존 010_shop.sql의 테이블을 사용하므로 추가 마이그레이션은 없다.

## 통신과 화면 처리

- 창을 열거나 탭·새로고침을 누르면 서버에서 다시 조회한다.
- 장착 응답 후 서버의 보유장비를 재조회해 전체 선택 상태를 갱신한다.
- 저장 중 중복 클릭은 무시한다.
- 결과 확인에 실패하면 새로고침으로 현재 상태를 확인하도록 안내한다. 요청 재전송은 명시적 목표 상태라 안전하다.
- 창을 닫거나 계정이 바뀐 후 도착한 이전 응답은 화면에 적용하지 않는다.
- 장착 도중 창을 다시 열거나 탭을 옮겼다면 완료 후 새 창의 데이터를 다시 읽는다.

## 검증

서버 빌드: 경고 0, 오류 0.

기존 구매 검사에 장착 검사를 추가해 실제 PostgreSQL 임시 스키마에서 총 55개 검사를 통과했다. 임시 스키마는 종료 시 정리한다.

```powershell
dotnet build Server/ShopPurchase.Tests/ShopPurchase.Tests.csproj --output "$env:TEMP/MagicOnline2-InventoryTests"
dotnet "$env:TEMP/MagicOnline2-InventoryTests/ShopPurchase.Tests.dll"
```

추가 검사에는 동시 장착 요청, 큐대·캐릭터 슬롯 분리, 미보유·다른 종류 거부, 사용자 분리, 비공개·만료·판매 중지 상품 장착, 재화 불변, 큐대 교체 후 이전 상품 해제, 메시지 다중 선택과 개별 해제가 포함된다.

실제 실행 API에서도 별도 검증 계정으로 상품 6개를 구매하고 다음을 확인했다. 일반 사용자의 보유장비와 잔액은 변경하지 않았다.

- 미인증 조회·저장 거부 및 빈 보유 목록.
- 구매한 상품 6개만 조회.
- 동일 장착 요청 8개 동시 전송 시 한 슬롯 유지.
- 큐대·캐릭터 교체와 메시지 두 묶음 선택.
- 다른 계정의 장착 시도 및 잘못된 슬롯 거부.
- 로그아웃·재로그인 후 선택 유지.
- 상점과 보유장비 조회의 장착 상태 일치.
- 장착 해제 시 다른 메시지 선택 및 보석 잔액 유지.

Unity의 기존 컴파일 응답 파일과 동일한 참조·정의로 런타임 및 에디터 코드를 별도 임시 출력에 컴파일해 통과했다. 열려 있는 에디터나 사용자 씬을 종료·변경하지 않았다.

`Tools > Local Game API > Verify owned equipment UI`에 미리보기 씬 기반 UI 검사도 추가했다. 이 메뉴는 계정을 생성하거나 서버 장착 상태를 변경하지 않으며, 보유장비 탭·페이지·장착/해제 버튼·빈 목록을 검사한다. 이 작업에서 해당 UI 실행 검사와 실제 화면의 시각적 검증은 수행하지 않았다.

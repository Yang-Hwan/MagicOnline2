# 장착 장비의 실제 경기 반영

작성일: 2026-11-12

## 적용 경로

현재 공개 멀티플레이에서 사용하는 Pavilion 경기와 친선 경기에 적용한다. 서버가 경기 ID별로 양쪽 참가자의 장착 정보를 고정하고, 두 클라이언트가 같은 서버 응답을 읽은 후 경기를 시작한다. 다른 물리 경로를 사용하는 개발용 Practice 멀티플레이 프로토타입은 이 연결 대상이 아니다.

장착 정보가 없으면 기존 기본 큐대와 기본 캐릭터를 사용한다. 실제 경기 중 상점·보유장비나 관리자 상품 설정이 바뀌어도 이미 시작한 경기의 장비 정보는 바뀌지 않는다. 재대결은 새 경기 ID로 최신 장착 정보를 다시 읽는다.

## 큐대 성능

| 설정 | 실제 반영 |
| --- | --- |
| 파워 | 기존 샷 충격량에 `1 + Power / 100` 배율 적용. -40%~+20% |
| 팔로스루 | 사용자가 선택한 팔로스루 값에 `1 + FollowThrough / 100` 배율을 적용하고 0~1로 제한. -40%~+20% |
| 당점 반경 | 당점 선택 UI의 허용 반경 및 안내 원에 `1 + Tip / 100` 적용. -10%~+10% |
| 샷 준비시간 | 기본 30초에 ShotSeconds를 더함. -5초~+5초 |

실제 샷과 50% 파워 예측선은 같은 계산 함수를 사용한다. 최종 샷 충격량·팔로스루·스핀 지속값은 기존 네트워크 샷 데이터에 담겨 전달되므로, 상대 물리 계산에서 장비 배율을 다시 곱하지 않는다. 턴마다 현재 타자의 고정 장비를 사용한다.

기존 timeInningSec는 프레임마다 감소하는 값이므로 새 턴의 장비 시간 계산에는 이 값을 재사용하지 않고 기본 30초를 사용한다.

## 캐릭터 이미지

- 장착한 캐릭터의 `기본` 이미지를 본인과 상대 경기 초상화에 적용한다.
- 득점은 `환희`, 파울은 `미안`, 실패는 `좌절` 표정을 표시하고 기본 표정으로 돌아온다.
- 경기 중 `메시지 / 표정` 버튼에서 아홉 감정도 직접 선택할 수 있다. 상대 화면에도 같은 감정이 전달된다.
- 결과·재대결 화면의 초상화에도 장착 캐릭터를 반영한다.
- Resources의 Sprite/Texture2D 키와 HTTPS 이미지 URL을 지원한다. 로컬 개발용 루프백 HTTP도 허용한다.
- 특정 감정 경로가 없으면 장착 캐릭터의 기본 이미지, 실제 파일을 불러오지 못하면 기존 내장 초상화로 대체한다.
- 다운로드 이미지와 생성한 Sprite는 컴포넌트 종료 시 정리한다. 늦게 도착한 다른 표정 다운로드가 현재 표정을 덮어쓰지 않도록 한다.

테스트 캐릭터 3개는 관리자 수정 폼을 통해 기존 BandanaAvatar/SilverAvatar의 실제 리소스에 연결했다. 각 감정에 기존 그림을 배정한 테스트 구성이며 새로운 캐릭터 그림을 생성한 것은 아니다. 변경 전 상품 내보내기는 로컬 임시 백업에 보관했다.

외부 이미지를 교체할 때는 버전이 포함된 URL 또는 새 리소스 키를 사용하는 것이 좋다. 경기 스냅샷은 리소스 키를 고정하며 외부 저장소의 같은 URL에 덮어쓴 파일 내용까지 보존하지는 않는다.

## 선택 메시지

경기 화면의 `메시지 / 표정` → `메시지`에서 장착한 메시지 묶음의 문장을 보낼 수 있다. 여러 묶음을 장착했다면 상품 정렬·문장 순서대로 합치고 동일 문장은 중복 제거한다. 다섯 항목씩 페이지를 이동한다.

- 텍스트 자체가 아니라 경기 ID와 목록 번호를 Photon RPC로 보낸다.
- 수신자는 서버에 고정된 동일 목록에서 문장을 찾는다.
- 경기 참가자의 실제 Photon Actor 번호와 범위를 확인해 미선택 문장·잘못된 번호·다른 경기 요청을 거부한다.
- 메시지와 표정은 합쳐서 약 2초 간격으로 보낼 수 있다.
- 본인·상대의 메시지는 구분된 말풍선 영역에 잠시 표시한다. TMP 리치 텍스트 해석은 끈다.
- 다음 경기로 넘어갈 때 이전 메시지 메뉴와 말풍선을 초기화한다.

## 서버 계약

011_match_equipment.sql의 match_equipment_snapshots에 경기별 고정 정보를 저장한다.

- 일반 경기: `/api/matches` 등록 과정에서 서버가 장착 정보를 생성한다.
- 친선 경기: 호스트가 `POST /api/matches/{id}/equipment`에 OpponentUserId를 보내 생성한다.
- 조회: 참가자만 `GET /api/matches/{id}/equipment`로 읽을 수 있다.
- 같은 경기 ID의 재시도는 기존 고정 정보를 반환한다. 다른 참가자·순서·친선 여부로 재사용하면 거부한다.
- 친선 API로 미리 생성한 정보를 일반 정산 경기의 장비로 사용할 수 없다.
- 사용자 지갑 공유 잠금과 상품 공유 잠금으로 장착·상품 수정 중에도 일관된 정보를 읽는다.
- 클라이언트가 능력치·이미지·메시지 목록을 지정하는 입력은 받지 않는다.

업그레이드 전 클라이언트와 장비 물리가 섞이지 않도록 매칭 프로토콜 문자열에 equipment1을 추가했다. 양쪽 클라이언트를 최신 코드/빌드로 실행해야 한다.

## 검증

- 서버 및 Unity 런타임·에디터 코드 컴파일 통과.
- 실제 PostgreSQL 임시 스키마에서 구매·장착·경기 고정·수치 계산 총 68개 검사 통과. 실사용자 지갑·장비를 수정하지 않는다.
- 실제 HTTP에서 양쪽 참가자의 동일 응답, 기본 장비, 선택한 메시지만 포함, 실제 캐릭터 리소스 키, 장착 변경 후 경기 정보 불변, 일반 경기 등록 시 최신 정보 반영, 참가자 외 조회 거부 및 친선/일반 경기 계약 분리를 확인했다.
- `Tools > Local Game API > Validate match equipment gameplay`에 실제 샷 생성 함수와 실제 UI Image를 사용하는 독립 검사를 추가했다. 사용자 씬 대신 미리보기 씬을 사용한다.
- 열려 있는 사용자 프로젝트와 분리한 임시 Unity 프로젝트에서 이 검사를 실행해 10개 항목을 통과했다. 실제 샷 생성 함수의 +20%/-40% 파워, 팔로스루 반영, 기본 충격량 보존, 실제 캐릭터 리소스 존재·UI Image 적용·감정 교체·대체 이미지 및 선택 메시지 번호 검증을 확인했다. 그래픽 장치 없이 실행했으므로 화면 배치의 시각적 QA를 뜻하지는 않는다.

서버 검사는 다음 명령으로 실행한다.

```powershell
dotnet build Server/ShopPurchase.Tests/ShopPurchase.Tests.csproj --output "$env:TEMP/MagicOnline2-MatchEquipmentTests"
dotnet "$env:TEMP/MagicOnline2-MatchEquipmentTests/ShopPurchase.Tests.dll"
```

2026-11-13 같은 Windows PC에서 두 개의 실제 개발용 플레이어를 실행해 정상 Pavilion 경기 경로를 검증했다. 실제 로그인·Photon 매칭·초구 배치 이후 양쪽에서 메시지/표정 UI를 사용하고 각자 샷을 쳤다. 양쪽의 동일 경기 장비 정보, 기본/감정 초상화, 서로 다른 장착 메시지, 파워·팔로스루·당점 범위·턴 제한 반영과 실제 공 이동, 기권 종료·서버 정산을 확인했다. 재현은 최신 개발 빌드 생성 후 `python Server/GameApi/Run-EquipmentE2E.py`로 실행한다. 상세 결과와 범위는 `EquipmentTwoClientTest.ko.md`를 참고한다.

외부 CDN 이미지 다운로드와 서로 다른 물리 기기·모바일 플랫폼 검증은 별도로 남아 있다. 서버는 기존과 마찬가지로 클라이언트 샷의 물리 시뮬레이션 자체를 검증하지 않으며, 이번 기능을 서버 물리 검증으로 해석하면 안 된다.

# 멀티플레이 감정·획득 코인 표시

## 적용 범위

Pavilion 씬의 멀티플레이 3구·4구에 적용한다. 연습용 `TableSet07`의 `Sentiment` 오브젝트 39개(글자 27개, 애니메이션 12개)를 `Table > Addition > Sentiment`에 독립 복사했다. 원본 `MovStorys`는 보존하고 신규 컨트롤러 초기화 후 기존 연출을 비활성화한다.

감정 종류·랜덤 선택·공 회피 글자 배치·수구 위치형 애니메이션은 연습과 같은 구성이다. 멀티플레이 전용 어댑터는 기존 멀티플레이 규칙의 `checkCushion`을 따르며, 경기 규칙이나 점수를 수정하지 않는다.

## 양쪽 감정 동기화

- 현재 샷의 권한을 가진 클라이언트만 접촉과 저속 이동으로 감정을 선택한다. 새 이벤트는 물리 충돌 계산 전에 관찰만 한다.
- 3구는 성공 확정 즉시, 4구는 정지 후 최종 판정에 성공 감정을 보낸다. 두 빨간 적구를 맞힌 뒤 단순 키스는 불만으로 표시하지 않는다. 상대 수구 파울은 여전히 반영한다.
- 3구에서 필수 쿠션이 3회이고 마지막 적구를 1·2쿠션 후 먼저 맞히면 속도와 무관하게 분노를 즉시 표시한다. 연습과 멀티플레이에 동일하게 적용하며 종료 시 좌절로 덮어쓰지 않는다. 감정만 변경하며 파울 감점은 추가하지 않는다.
- 3구의 실망은 설정된 필수 쿠션 수를 충족한 뒤 저속으로 마지막 적구를 아깝게 지나칠 때만 표시한다. 충족 전의 접근 기록은 초기화한다. 싱글 연습과 멀티플레이에 동일하게 적용하며 4구 조건은 유지한다.
- `SentimentMotionRPC`는 경기 ID·샷 일련번호·상대 ActorNumber·샷 시작 시 저장한 권한을 검사한다. 샷 시작보다 먼저 도착한 메시지는 최대 5초 기다리고, 중복·과거 샷 메시지는 제외한다. 현재 턴이 바뀌어도 해당 샷의 마지막 감정은 받을 수 있다.
- 샷 종료 감정은 샷 종료 패킷보다 먼저 보낸다. 상대가 턴을 바꾼 뒤 마지막 감정을 거부하는 문제를 피한다.
- 샷 시작에 `isCueBall`로 실제 수구 객체를 저장한다. 자신/상대를 뜻하는 `turnId`를 공 ID로 사용하지 않는다. 감정 결정 순간의 수구 월드 위치를 감정·선택 seed와 함께 전달하며, 상대도 전달된 위치에서 연출한다. 턴 전환 후 다른 수구를 다시 찾거나 따라가지 않는다. 상대는 독립적인 점수 판정이나 정산을 하지 않는다.
- 새 샷·화면 비활성화 시 이전 연출을 정리한다. 연출은 경기 상태를 대기시키지 않는다.

## 획득 코인 숫자

- `PunNetwork.SelfCoinGain`(기존 확정/3구 상대 턴 미리보기 원장)을 표시 목표값으로 사용한다. 보유 코인은 기존 원장값을 표시한다.
- 목표 획득액이 바뀌면 기존 획득액에서 시작해 동전 도착 수에 비례하여 증가/감소한다. 상대 숫자는 반대 부호이며 마지막 도착에서 목표값을 정확히 대입한다.
- 원장의 득점 횟수·연타 배수·잔액 제한·수수료·DB 정산은 변경하지 않는다. 새 `AddVisualCoin`은 기존 `Coins` 지급 setter를 호출하지 않는다.
- 기존 득점 메시지 배너는 숨기고 코인 모션은 유지한다. 득점 확정과 LateUpdate가 같은 모션을 두 번 실행하지 않게 기존 경로를 건너뛴다.
- 연속 득점이나 보정으로 목표값이 바뀌면 현재 표시값에서 다시 시작한다. 취소 토큰·표시 버전으로 이전 도착 콜백을 무시한다. 화면 전환/재대결 시 상태를 초기화하고 날아가는 표시용 코인을 풀로 돌려보낸다.
- 코인 풀에 여유가 없으면 해당 표시 진행분은 즉시 반영해 최종 숫자가 부족하게 남지 않게 한다.

## 검증 범위

턴 전환 위치 회귀 검증: 3구·4구 × 자신/상대 순서 × 흰공/노랑공의 8가지 조합에서 종료 시 턴과 수구 플래그가 바뀌어도 원래 샷의 위치를 전송하고, 표시 측 애니메이션이 전달된 고정 위치를 받는지 확인했다.

컴파일과 분리된 Unity 이벤트 검증: 3구 즉시 성공, 4구 최종 성공, 양쪽 수구 역할, 고속/저속 파울, 득점 후 키스 무시, 실패·감사·안도, 상대의 표시 전용 경로, 양수/음수/큰 금액의 최종값 반올림을 확인한다. 실제 Photon 두 클라이언트를 연결한 경기 및 전체 게임 성능 프로파일링은 별도이며, 양쪽 클라이언트에 같은 변경이 포함된 빌드가 필요하다.

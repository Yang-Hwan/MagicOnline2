# 큐대 바가지 성장

## 사물함 UI (2026-11-25)

- 큐대 스킨·장착 영역 아래의 독립된 `큐대 성장` 패널 안에 진도, 5개 능력치, 모두성장 버튼을 묶는다. 진도는 상단의 큰 글자와 넓은 노란 게이지로 강조하며 계층 연결선은 사용하지 않는다.

- 상세 제목에는 큐대 명칭과 등급만 표시한다. 최저 능력치로 만든 대표 레벨은 표시하지 않으며, 성장 연출 중에도 다시 넣지 않는다.
- 성장 예정 구간은 별도 사각형 대신 현재 그래프와 같은 메시를 연장해 그린다. 현재 값의 경계에서 이후 구간에만 42% 알파를 적용하므로 색·광택·외곽선이 끊기지 않는다.

- 최종 블루 스포츠 스타일: 네이비 패널, 블루 그라데이션 배경, 하늘색 제목 띠·장착 버튼, 노란 성장 버튼, 연두색 그래프를 사용한다. 도트와 당구공 링 실루엣은 `CueLockerGraphic` 메시로 그리며 카드 스크롤 마스크에 맞춰 잘린다. 별 등급·분해·진화 기능은 추가하지 않는다.
- 성장 알림에는 잎 장식을 넣지 않는다. 상세 팝업에는 닫기 버튼을 두지 않고 바깥 영역 클릭으로 닫는다. 그래프 수치 설명과 표 헤더, 하단 성장 안내 문장은 표시하지 않는다.

- 큐대 목록은 가로 스크롤이며, 1430 너비의 영역에 920 너비 카드와 다음 카드 약 절반이 보인다. 카드에는 등급·명칭·스킨·장착 상태를 표시한다.
- 수동 승인 가능한 바구니가 하나 이상일 때만 `성장!` 알림을 표시한다. 알림은 버튼이 아니며 카드 클릭은 상세 팝업만 연다.
- 상세 화면의 행 순서는 파워·밀기(팔로스루)·스핀(당점)·조준(가이드)·시간이다. 서버 능력치 인덱스는 0/1/2/4/3으로 매핑한다.
- 차트는 `(현재 레벨 - 초기 레벨) / (최대 레벨 - 초기 레벨)`을 사용한다. 레벨 숫자는 등급 적용 값이다. 초기·최대가 같으면 꽉 찬 차트다.
- `성장`은 해당 바구니의 기존 마시기 API를 호출한다. `모두성장`은 클릭 시 준비된 항목만 표시 순서대로 승인한다. 상품 자동 승인 설정과 기존 진도·레벨 계산은 바꾸지 않는다.
- 서버 성공 응답 후 행의 빛 확산·반짝임을 재생하며 실제 증가한 레벨과 차트만 보간한다. 처리 중 중복 입력을 막고, 닫힌 팝업을 다시 열지 않는다. 실패하면 재시도 전에 새로고침을 안내한다.

큐대별로 파워·팔로스루·당점·시간·가이드 바가지를 가진다. 기본 최대값은 20/10/30/20/40이며 관리자 > 상점 > 큐대 편집에서 각각 1~10,000으로 설정한다. 기존 회원의 레벨·성장 진도는 보존한다. 현재 바가지 회차는 시작 당시 최대값을 유지하고 다음 회차부터 최신 상점 최대값을 사용한다.

정상 득점 1점마다 가득 차지 않은 항목 하나를 같은 확률로 골라 +1한다. 뱅크샷 2점은 두 번 배분한다. 최대 레벨(그래프 100%)에 도달한 항목은 완료로 표시하고 배분·승인 대상에서 제외한다. 가득 찬 항목과 이미 마신 항목도 배분 대상에서 제외한다. 모두 가득 차면 추가 득점은 소멸한다. 대기 득점이나 다음 회차로 넘어가는 잔고는 없다. 중복 전송을 막는 이벤트 식별자는 남기므로, 버려진 득점도 마시기 이후 재전송해서 받을 수 없다.

회원 > 사물함 > 큐대 상세에서 각 바가지의 현재값/최대값과 승인 상태 및 상품의 자동 마시기 여부를 확인하고 `마시기`를 누른다. 최대 레벨이 아닌 성장 가능 항목을 모두 승인하면 진도 +1과 함께 바가지를 초기화한다. 모든 항목이 최대 레벨이면 득점을 배분하지 않고 진도도 증가시키지 않는다. 진도가 기존 도달 진도에 도달하면 능력치 레벨이 최고 레벨까지 1씩 오른다. 이미 마신 항목은 누적값을 0으로 소비하고 회차가 끝날 때까지 잠긴다. 서버 승인은 즉시 저장한다. 유니티는 화면에서만 0.3초마다 +20 → +19처럼 1씩 감소시키며, 해당 그래프 내부 RectMask2D 영역에서 오른쪽→왼쪽 빛을 반복한다. 팝업을 닫으면 연출만 중단되고 다시 열면 최종 저장 상태를 표시한다.

자동 마시기는 관리자 상점의 큐대 상품 설정이며 기본 꺼짐이다. 해당 상품을 보유한 모든 회원에게 공통으로 적용하고 회원은 변경할 수 없다. 관리자가 켜면 다음 회원 정보 조회 또는 득점 처리에서 이미 가득 찬 항목도 승인하고 이후 가득 찬 항목을 자동 승인한다. 끄면 다음 조회/득점부터 수동 승인으로 돌아가며 이미 마신 항목의 승인은 유지한다. 마지막 승인 전후 득점과 중복 요청은 회원 지갑 행 잠금 아래 같은 트랜잭션으로 처리한다. 성장 후 성능은 기존 규칙대로 다음 경기/연습 입장에서 반영하며 진행 중인 장비 스냅샷은 바꾸지 않는다.

API:

- `POST /api/me/cue-progress/practice`: 기존 득점 보고에 `Points`(1~2, 생략 시 1)를 추가. 연습·친선·길드전 경로에서 사용한다. 일반 대전은 기존 합의 정산의 점수 이벤트에서 지급한다.
- `POST /api/me/cue-bowls/drink`: `CueId`, `Operation`(GUID), `Cycle`, `Index`(0~4, -1은 현재 승인 가능한 항목 전체를 한 트랜잭션으로 처리). 가득 차지 않았거나 오래된 회차는 409로 거절한다.
- 회원용 `/api/me/cue-bowls/auto` 변경 API는 제거했다. 관리자 상품 편집의 `BowlAuto`를 서버가 읽는다.
- `/api/me/inventory`와 상점 응답의 `CueBowls`: `Maximum`, `Filled`, `Drunk`, `Auto`, `Cycle`.

회원 인증과 보유 큐대 검사를 거치며 다른 회원의 상태는 수정할 수 없다. 관리자 회원 큐대 탭에는 바가지 현황과 자동 마시기 상태를 표시한다. 관리자의 큐대 성장 초기화는 바가지도 초기화하고 회차를 증가시킨다. 이전 득점/승인 식별자는 유지한다.

DB 변경은 `026_cue_bowls.sql`과 상품 자동 마시기 타입을 검사하는 `027_cue_bowl_product_auto.sql`이다. API 시작 시 기존 마이그레이션 경로로 적용한다. 기존 마이그레이션 파일은 수정하지 않는다.

검증:

```powershell
dotnet build Server/GameApi/GameApi.csproj --output Logs/Bowls/GameApi
python Server/GameApi/Run-CueBowlsSmoke.py
```

HTTP 검증은 격리 PostgreSQL 스키마와 임시 서버를 만들고 종료 시 제거한다. 관리자 입력·회원/비회원 권한·무효 득점·수동/자동 승인·설정의 다음 회차 반영·동시 중복 요청을 확인한다. 운영 회원이나 상품을 테스트용으로 수정하지 않는다.

# 길드 기능

홈의 `길드` 타일에서 진입한다. 하단 메뉴와 기존 홈 화면은 유지하고, `길드 홈 / 길드원 / 길드 찾기` 탭으로 구성했다. 길드가 없으면 찾기 탭을 먼저 연다.

## 사용 흐름

- 만들기: 길드명 2~20자, 영문/숫자 태그 2~6자, 소개와 가입 방식을 입력한다. 생성 비용은 없고 정원은 30명이다. 한 회원은 한 길드에 가입할 수 있다.
- 찾기: 길드명·태그 검색, 자유/승인 가입 필터, 페이지 이동을 지원한다. 자유 가입은 즉시 가입하고 승인 가입은 운영자에게 신청한다. 신청 취소도 가능하다.
- 초대: 길드장·부길드장은 닉네임으로 실제 회원을 찾아 초대한다. 수신자는 홈의 알림 또는 찾기 탭의 받은 초대에서 가입/거절한다. 초대 유효기간은 7일이다.
- 홈: 실제 길드 정보·길드장·인원·접속 수·공지·채팅을 표시한다. 공지는 클릭하면 전문을 볼 수 있다. 채팅은 서버에 보관하며 최근 50개 이후 커서로 이어 읽고 화면에는 최대 200개를 유지한다.
- 길드원: 장착한 기본 표정 캐릭터, 닉네임, 레벨, 직책, 접속/경기 중/오프라인 상태를 표시한다. 닉네임 검색과 접속 중 필터를 지원한다. 아바타·이름을 누르면 기존 선수정보 창에서 실제 전적·획득상금·큐대를 조회한다.
- 친선경기: 접속 중인 다른 길드원의 경기 신청을 누르고 경기장을 고른다. 기존 친선경기 알림 → 수락 → Photon 방 입장 경로를 그대로 사용한다. 친구 추가가 없어도 같은 길드라면 신청할 수 있다. 친선경기는 입장 무료·공식 기록 미반영 정책을 유지한다.

## 권한과 동기화

길드장과 부길드장은 공지·소개·가입 방식 수정, 신청 승인/거절, 초대를 할 수 있다. 직책 변경과 길드장 위임은 길드장만 가능하다. 부길드장은 일반 길드원만 추방할 수 있다. 다른 길드원이 있으면 길드장은 위임 후 탈퇴해야 하며, 마지막 회원이 탈퇴하면 해산한다.

화면은 5초 간격으로 갱신한다. 접속 상태는 기존 친구 presence를 공유하고 40초간 갱신이 없으면 오프라인으로 표시한다. 채팅 발송은 서버에서 2초 간격을 제한하며 요청 UUID로 재전송 중복을 막는다. 공지 수정은 revision으로 동시 수정 충돌을 감지한다.

가입·초대 수락·승인·탈퇴는 회원과 길드를 잠그는 DB 트랜잭션으로 처리한다. 동시 가입에도 정원과 1인 1길드를 보장한다. 탈퇴·추방 시 해당 길드에서 시작한 친선경기 요청을 종료한다. 관리자 회원 삭제 시 길드에서도 제거하고, 길드장이 삭제되면 남은 부길드장/가입 순서 기준으로 새 길드장을 정한다. 모두 삭제되면 해산한다. 기존 구매·경기·회계 이력은 기존 삭제 정책을 따른다.

## 구현 위치

- Unity: `BottomMenuView.Guild.cs`, `BottomMenuView.GuildForms.cs`, `GuildEmblemGraphic.cs`, 공용 `GuildData.cs`.
- API: `/api/guilds` 인증 경로와 `Guilds*.cs`. 길드원 선수정보는 `/api/guilds/{guild}/members/{user}/profile`.
- DB: `017_guilds.sql` — 길드, 회원, 신청, 초대, 채팅, 감사 이력, 생성 중복 방지, 친선경기 길드 연결.
- 기존 친구 알림/경기 연결은 `Friends.cs`, `FriendSocial.cs`를 확장했다.

## 검증

`dotnet run --project Server/Guild.Tests/Guild.Tests.csproj`는 실제 로컬 PostgreSQL의 임시 스키마에서 40개 검사를 실행하고 스키마를 정리한다. 생성 재시도·승인·초대 만료와 수신자 권한·운영자 강등·공지 충돌·채팅 권한과 중복·상태 갱신·친선경기 양측 티켓·탈퇴 철회·동시 정원/중복 가입·삭제 후 길드장 복구를 검증한다.

`python Server/GameApi/Run-GuildSmoke.py`는 API 5080과 관리자 5082에서 테스트 계정 3개로 HTTP 흐름 30개를 확인하고 관리자 삭제 폼으로 해당 계정만 정리한다. 로컬 개발 환경 전용이다.

Unity 메뉴 `Tools / Magic Online / Validate Guild Screens`는 독립 미리보기 씬에서 홈·길드원·찾기·생성 폼을 렌더링하고 입력·경기 버튼 상태를 확인한다. 산출물은 `Logs/Guilds`에 기록한다. 실제 두 Unity 클라이언트의 Photon 경기 전체 실행은 이번 검증에 포함하지 않았다. 기존 친구 친선경기 경로를 공유하며 서버에서 양측 수락 티켓을 검증했다.

실행 중인 에디터 플레이는 중단하지 않았다. 새 메뉴 코드는 플레이 종료와 재진입 후 반영된다. 기존 배포 클라이언트에는 새 빌드가 필요하다.

### 초대 없음 응답 처리

Unity `JsonUtility`는 서버의 `GuildInvite: null`을 ID가 빈 객체로 복원할 수 있다. 알림은 초대 ID와 길드 ID가 모두 유효한 UUID일 때만 표시하고, 수락/거절 직전에도 초대 ID를 검사한다. 같은 방식으로 `/api/guilds/me`의 `Guild: null`을 빈 길드로 취급하지 않도록 정규화한다. `Tools / Magic Online / Validate Guild Notifications`에서 실제 Unity JSON 역직렬화로 이 사례와 정상 초대·소속 정보를 검증한다.

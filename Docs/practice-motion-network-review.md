# 연습 공 이동 개선 및 네트워크 점검 (2026-09-20)

## 수정

- 연습 씬은 100 Hz 고정 스텝 안에서 4회 물리를 직접 계산하지만 공 Rigidbody의 보간은 꺼져 있었다. 화면 프레임과 고정 스텝이 맞지 않으면 공의 표시 이동량이 불규칙해질 수 있다.
- 각 고정 스텝 직전의 위치/회전을 저장하고 LateUpdate에서 공 메시만 보간한다. 1 고정 스텝(10 ms)의 표시 지연을 허용하며 Rigidbody, 충돌체, 샷 기록 및 득점 계산은 바꾸지 않는다.
- 그림자와 운동 상태 표시도 보간된 공 위치를 따른다. 정지, 배치, 되돌리기, 리플레이에서는 실제 위치로 즉시 복귀한다.
- 리플레이 기록 객체와 배열은 입장 시 3,000 프레임(30초)을 준비하고 다음 샷에서도 재사용한다. 더 긴 샷은 필요한 만큼 확장하며 기존 30,000 프레임 상한을 유지한다.
- 운동 상태 문자열은 미리 정한 형식을 사용해 매 화면 프레임의 문자열 연결 할당을 제거했다.

물리 갱신과 화면 갱신 간 보간의 목적은 [Unity Rigidbody interpolation 문서](https://docs.unity.com/en-us/engine/6000.7/script-reference/unityengine/rigidbody/interpolation)에도 설명되어 있다. 이 프로젝트는 수동 서브스텝을 사용하므로 화면용 메시를 별도로 보간한다.

## 네트워크 확인 결과

기존 온라인 대전과 연습은 다른 PhysicsMng/Ball 클래스를 사용한다.

- `Assets/Scripts/Exert/Network/PunNetwork.cs`: Photon PUN RPC 전송, 전송 주기 설정 10 Hz, 방 최대 2명.
- `Assets/Scripts/Sight/Surface/Pavilion/PnlMatch.cs`: 샷 impulse 전송/수신.
- `Assets/Scripts/Sight/Vital/Pavilion/Ball.cs`: 시작/충돌/종료 시 위치·선속도·각속도 상태 전송. 수신 측은 샷 내 시간에 맞춰 기다린 뒤 상태를 직접 적용한다.
- `Assets/Scripts/Exert/Match/PoolNetMsg.cs`: 기존 Pavilion 물리 관리자와 Ball에만 연결한다.
- 연습 `PhysicsMng.Items.cs`의 ConfigureItemSession은 아이템 권한/세션 진입점이다. 현재 Photon 수신부와 연결된 호출은 없다. 연습 물리와 공 이동 전체를 네트워크화하는 구현은 아니다.

따라서 기존 대전에는 동기화 기반이 있으나, 연습의 개선된 물리를 그대로 온라인에서 동기화할 수 있다고 판단할 수는 없다. 현재 연습은 로컬이다. 기존 대전도 두 클라이언트 실제 접속/지연 테스트를 하지 않았으므로 정상 동기화를 보증하지 않는다.

기존 구현의 추가 검토점:

- 지연된 공 상태를 현재 위치에 즉시 덮어쓰므로 수신 화면이 튈 수 있다.
- 공 상태 메시지에 match/shot 번호 및 순번이 없어 오래된 샷의 비동기 대기 작업을 확실하게 구분하기 어렵다. 대기 루프에도 파괴/샷 교체 취소 토큰이 없다.
- 각 클라이언트의 물리 결과가 항상 동일하다고 전제하면 안 된다. 권한을 가진 한 쪽의 주기적 스냅샷과 최종 위치·득점·턴 확정, 수신 측 보간이 필요하다.

연습 물리를 온라인으로 연결할 때에는 샷/공 ID·순번·타임스탬프, 권한 검증, 주기적 위치/회전/속도 스냅샷, 최종 상태 확정 및 지연 버퍼를 마련하고 2개 클라이언트에서 지연/연결 종료/턴 전환을 검증해야 한다. 이번 변경은 연습 표시 개선에 한정하며 기존 대전 프로토콜을 변경하지 않았다.

## 검증

`Tools > Magic Online > Validate Practice Integration` 및 `Logs/practice-validation.json` 사용.
3구/4구 샷에서 메시 보간의 양 끝점/중간점과 Rigidbody 상태 불변, 정지 표시 복귀를 추가 검사한다.
리플레이 슬롯 재생, 메뉴 복귀 및 전역 물리 설정 복원은 기존 회귀 검증에 포함된다.
수정 전 런타임 파일은 `Logs/MotionFixBackup`에 보관했다.

최종 Unity 6000.5.7f1 검증: passed=true, 3구/4구 샷 2회, 화면 보간/물리 불변 검사 2회,
저장 리플레이 15개 재생, 3회 입장 및 메뉴 복귀, 전역 물리 설정 복원 통과.
누락 스크립트/참조/지원하지 않는 재질/런타임 오류 0개.
초기 검증은 편집기 코드 갱신과 겹쳐 중단되었으며, 컴파일 완료 후 새로 실행한 위 결과가 최종 결과다.
실행 파일 재빌드, 전후 프레임 시간 프로파일링 및 실제 2인 온라인 접속은 수행하지 않았다.
따라서 체감 끊김 전체가 제거되었다는 성능 보증은 아니며, 수정된 연습 씬에서 플레이 확인이 필요하다.

# 경기 중 선수정보와 메시지 클릭 영역

멀티플레이 경기 화면의 본인·상대 아바타는 해당 선수의 정보 창을 연다. 메시지 묶음은 본인 또는 상대의 대기시간 게이지 영역을 눌러 연다. 두 게이지 모두 본인의 메시지 묶음을 열며, 타인의 메시지를 대신 보내지 않는다. 클릭 영역은 채움 막대가 아니라 고정된 TimeInning 영역이므로 남은 시간이 적어도 사용할 수 있다.

## 선수정보

- 장착 캐릭터의 기본 이미지, 실제 닉네임과 바로 옆의 작은 레벨 표시.
- 한국 시간의 오늘 정산 기록에서 현재 이어지는 승리가 2회 이상일 때만 `금일 N연승` 배지 표시. 없거나 1승이면 공간을 비워 둔다. 금일 승/패 합계는 표시하지 않는다.
- 총 획득 상금, 전체/4구/3구 승률과 승/패 기록. 무승부가 있으면 횟수도 함께 표시한다.
- 실제 장착 큐대의 상품명·설명·이미지와 파워/팔로스루/당점 범위/제한시간 보정.
- 닫기 버튼과 바깥 영역으로 닫을 수 있다. 화면 비율에 맞춰 전체 창을 축소한다.

조회 중에는 로딩 안내, 실패 시 재시도 버튼을 표시한다. 다른 계정·경기로 바뀌거나 창을 닫은 후 도착한 응답은 적용하지 않는다. 창 조작이 뒤쪽 조준·파워 드래그로 전달되지 않도록 샷 입력을 차단하며, 이미 진행 중인 공 이동과 네트워크 샷은 계속 처리한다.

## 집계 기준과 API

`GET /api/matches/{id}/players/{seat}` (seat 0 또는 1). 인증과 해당 서버 장비 스냅샷의 참가자 검사를 거친다. 상대의 지갑 잔액이나 인증 정보는 반환하지 않는다.

닉네임·레벨·종목별 전적은 실제 users/user_stats에서 읽는다. 전체 전적에는 미분류 레거시 승/패도 합산한다. 승률은 승/(승+패)이며 무승부는 분모에서 제외한다. 전적이 없으면 0.0%다.

총 획득 상금은 보존된 settlement_receipts의 승리 정산 Reward 누적이며 보유 코인 잔액이나 순손익과 구분한다. 환급·무승부·취소·우편 보상은 합산하지 않는다. 6개월 상세 경기 기록이 정리된 뒤에도 영구 정산 영수증으로 집계한다. 영수증 없이 이관된 과거 전적의 상금을 추측하여 채우지는 않는다.

금일 연승은 정산 시각을 한국 날짜로 구분하고 최신 승리에서 역순으로 센다. 패배·무승부를 만나면 멈추고, 취소 경기는 제외한다. 전날 승리는 오늘로 이어 붙이지 않는다.

캐릭터·큐대 능력치는 경기에서 실제 사용 중인 고정 장비 정보다. 큐대 이름/설명/썸네일은 등록된 상품 데이터를 사용한다. 이미지가 없으면 미등록 안내를 표시한다.

## 검증

- 서버/Razor 및 Unity 런타임 코드 컴파일.
- PostgreSQL 임시 스키마에서 집계·자정 경계·승/패/무/취소·장비·참가자 권한 등 18개 검사 통과.
- 실행 중인 API에서 실제 가입한 3개의 테스트 계정으로 본인·상대 정보, 동일 응답, 0 전적, 외부인/비로그인/잘못된 좌석 거부 등 HTTP 9개 검사 통과. 테스트 계정은 관리자 삭제 흐름으로 정리했다.
- 분리한 Unity 환경에서 실제 UI Image/TMP와 큐대 이미지를 사용해 10개 검사 및 1280×720, 1024×768, 960×540 렌더 확인. 배지 유무와 게이지 채움이 비어도 유지되는 클릭 영역을 검사한다.
- 두 클라이언트 실경기 자동화에도 본인/상대 정보와 서버 응답 비교, 두 게이지의 메시지 메뉴 열기, 화면 캡처 검사를 추가했다. 이번 변경 후 새 플레이어 빌드의 두 클라이언트 실행은 아직 하지 않았다.

```powershell
dotnet build Server/PlayerInformation.Tests/PlayerInformation.Tests.csproj --output "$env:TEMP/MagicOnline2-PlayerInfoTests"
dotnet "$env:TEMP/MagicOnline2-PlayerInfoTests/PlayerInformation.Tests.dll"
```

Unity 메뉴: `Tools > Magic Online > Validate Player Information`. 예시 데이터를 이용한 UI 배치 검증이며 실제 API 집계 검증과 구분한다. 화면과 결과는 `Logs/PlayerInformation/`에 저장한다. 실제 경기 자동화는 최신 개발 빌드를 만든 후 `python Server/GameApi/Run-EquipmentE2E.py`로 실행한다.

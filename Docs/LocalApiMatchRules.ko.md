# 서버와 클라이언트 경기 규칙 일치 처리

2026-10-18 구현. 경기 규칙 계약 버전은 `MatchRulesContract.CurrentVersion = 1`이다.

## 시작 승인

- 로그인 후 차트를 읽기 전에 인증된 `GET /api/match-protocol`의 버전을 확인한다. 구형 서버의 404 응답도 버전 불일치로 안내한다.
- 경기 등록 요청에는 경기장 번호와 함께 클라이언트의 규칙 계약을 보낸다. 서버는 현재 경기장 차트로 계약을 직접 생성하고 비교한 뒤 그 계약을 경기 행에 보관한다.
- 계약은 종목, 목표 점수, 쿠션, 경기 시간, 턴 시간, 마무리 미션, 입장료, MaxCoin, 연결 만료 정책, 지급 정책 및 실행 경로를 포함한다.
- 일반 Pavilion은 턴 30초, 개발용 Practice는 턴 20초를 사용한다. 4구의 실제 목표 점수는 기존 실행 코드와 같은 3점이다.
- 두 참가자의 준비 요청에도 각각 자신의 로컬 규칙을 보낸다. 상대방이 보낸 규칙을 그대로 승인 값으로 사용하지 않는다.
- 서버는 경기 및 지갑 잠금 트랜잭션 안에서 저장된 계약과 비교한다. 불일치 예외는 준비 상태 변경 및 입장료 차감 전에 발생한다.
- 두 참가자의 계약이 일치하고 양쪽 준비가 끝나야 기존 입장료 차감 흐름으로 넘어간다.

## 차트 갱신 및 재요청

새 경기 등록은 현재 서버 차트를 기준으로 한다. 같은 경기 ID의 재등록은 최초 등록된 계약과 비교하므로 차트가 나중에 바뀌어도 같은 요청을 재시도할 수 있다. 준비 요청도 최초 계약을 기준으로 한다. 새 차트를 받은 참가자는 이전 규칙의 경기에는 참가할 수 없다.

계약이 없던 구형 대기 경기는 새 API에서 준비 승인하지 않는다. 이미 시작한 구형 경기의 결과·기권·복구 요청은 기존 경로로 처리한다. 정산이 완료된 영수증은 계속 중복 지급을 막는다. 계약 상세는 기존 규칙 스냅샷과 함께 6개월 이후 정리 대상이다.

## 오류와 배포

- `MatchProtocolMismatch`(409): 게임과 서버 버전 차이 및 업데이트 안내.
- `MatchRulesMismatch`(409): 다시 로그인하여 경기장 정보 갱신 안내.
- `UnsupportedMatchRuntime`, `UnsupportedMatchRules`(409): 지원하지 않는 경기 규칙 안내.
- 본문 없는 구형 준비 요청은 새 요청 형식을 충족하지 못한다.

Photon 일반/개발 방 버전도 변경하여 이전 플레이어와 같은 방에 섞이지 않게 했다. 서버와 Unity 플레이어를 함께 갱신해야 한다. 이전 빌드의 대전 통과 기록은 이 계약 버전의 검증 결과로 간주하지 않는다.

개발용 목표 점수·시간 변경 옵션도 서버 차트와 일치해야 한다. 로컬 옵션만으로 입장료가 있는 경기의 서버 규칙을 우회할 수 없다.

## 확인 범위

서버 빌드는 경고 0개·오류 0개로 완료했고 `Logs/GameApi-Rules/`에 출력했다. Unity도 새 계약 파일을 임포트하여 Assembly-CSharp 및 Editor 어셈블리를 다시 컴파일했다. 이번 변경에 대한 HTTP·DB 회귀 검사 및 실제 두 플레이어 대전은 실행하지 않았다. 기존 검사 프로그램의 등록·준비 요청 형식은 새 계약에 맞춰 갱신했다.

실행 중인 로컬 API의 중지·재시작 요청은 자동 승인 검토에서 `blocked by policy`로 거절됐다. 따라서 실행 중인 서버는 이전 버전이며 새 서버 적용은 남아 있다. 이번 계약이 포함된 Windows 플레이어도 아직 새로 빌드하지 않았다. 서버 재시작과 Unity 재빌드를 함께 진행한 뒤 대전을 확인해야 한다.

이 계약 비교는 양쪽이 같은 규칙으로 시작하도록 하는 장치다. 서버 물리 시뮬레이션, Photon 사용자 인증, 결과 공모 방지 및 분쟁 처리 절차는 후속 작업이다.

# 결과 보고 검증 및 계정별 재전송 큐 검사

2026-10-15. 기존 실행 결과는 `LocalApiClientE2E.ko.md`에 보관한다.

## 수정한 경로

- 공개 경기의 `HistoryResultRPC`는 상대방의 알림이며 내 인증 결과로 변환하지 않는다. 점수·승자가 일치하는 0:0 무승부도 경기 중에는 위조할 수 있기 때문이다. 상대 메시지로 로컬 경기 종료·결과 화면 전환·정산 요청을 수행하지 않는다.
- 내 결과 화면과 기존 결과 전송 진입점도 로컬 게임의 종료 상태를 확인한다. 승자는 호출자가 전달한 승리 플래그 대신 로컬 최종 점수로 정한다. 기권·연결 만료는 기존 서버 판정 경로를 사용한다.
- 서버 `ConfirmResult`는 승자와 점수의 일치를 확인한다. 낮은 점수 쪽 승리, 동점 승리, 점수가 다른 무승부를 거부하고 기존 경기·잔액을 유지한다.
- Unity API의 인증 갱신 후 재시도에서도 로그인 세대와 사용자 ID를 요청 전후에 확인한다. 응답 대기 중 계정이 바뀌면 이전 계정의 결과를 새 로그인 작업에 반환하지 않는다. 동일 사용자 재로그인도 로그인 세대로 구분한다.

## 실행 방법

로컬 API와 최신 Unity 개발 빌드, 검사용 경기장 9003/9004가 필요하다. 프로젝트 루트에서 실행한다.

```powershell
./Server/GameApi/Run-ClientE2E.ps1 -Mode public-guard -HallId 9004
./Server/GameApi/Run-ClientE2E.ps1 -Mode public-guard -HallId 9003
./Server/GameApi/Run-ClientE2E.ps1 -Mode isolation
```

`public-guard`는 양쪽 실제 Photon 클라이언트에서 정상 경기 시작 후 상대에게 조기 0:0 무승부, 조작한 승리/점수, 다른 경기 ID의 결과를 보내고 자기 결과 전송 진입점도 조기에 호출한다. 6초 뒤에도 서버 Playing·로컬 경기 진행·대기 요청 0건·결과 화면 미표시인지 확인한다. 이어서 실제 시간 종료와 정상 정산·화면 갱신을 검사한다. 중간 검증은 각 `A.json.guard.json`, `B.json.guard.json`에 기록한다.

`isolation`은 실제 경기 결과를 A의 큐에 저장하고 앱을 종료한다. 새 프로세스에서 C로 가입·로그인해 6초간 일반 재전송 루프를 실행한다. C의 큐 0건, A 경기 조회 404, 결과 제출 403을 확인한다. A로 다시 로그인했을 때 기존 요청 1건과 미정산 상태가 유지되는지 확인한 뒤 재전송·정산·큐 0건까지 검사한다. C의 식별자와 검사 결과는 `A.json.isolation.json`, 종료 전 A 상태는 `A-before-restart.json`에 기록한다. 계정 비밀번호와 토큰은 출력하지 않는다.

## 검증 범위

이 변경은 정산 트랜잭션의 중복 방지와 별개로 결과 입력 경로를 보강한다. 서버가 공의 움직임을 재현해 승패를 증명하는 구현은 아니다. 수정된 두 클라이언트가 직접 API에 거짓 보고를 일치시켜 보내는 공모, 물리·턴 RPC의 전체 검증, Photon 사용자 ID와 API 계정의 서버 인증 연결은 추가 설계 대상이다. 인증 갱신 재시도 중 계정 전환의 경합은 코드 검토로 보강했고, 재시작 후 다른 계정 큐 격리 검사와 구별한다.

공개 4구·3구의 각 클라이언트에서 조작 시도 4회씩, 총 16회를 수행했다. 양쪽 `guard.json`의 `Phase=Playing`, `Pending=0`, `Ok=true`를 확인했다. 정상 시간 종료 후 양쪽 `Ok=true`, `SawOutcome=true`, `RematchEnabled=true`, 코인 30이었다. 가입 폼·공개 경기장 진입 경로와 Pavilion 단일 로드도 통과했다.

계정 격리 검사는 실제 물리 타격 후 A의 결과 1건을 파일에 저장하고 앱을 종료했다. 새 프로세스에서 다른 계정 C로 로그인했을 때 `OtherPending=0`, 원래 경기 조회 404, 결과 제출 403을 확인했다. A로 다시 로그인하면 `OriginalPending=1`이 보존됐고 재전송 후 `PendingAfterRestart=0`, 정상 무승부 정산·코인 30으로 완료됐다. C는 코인 30과 전적 0을 유지했다.

PostgreSQL에서 세 경기 모두 `Applied`, 분쟁 없음, `MutualConfirmation`을 확인했다. 경기당 영수증 1개·공통 기록 1개·개인 기록 2개·입장/정산 원장 4개였다. 참여자 6명과 격리 검사 계정 C의 총 7개 지갑에서 `coin = SUM(wallet_ledger.coin_delta) = 30`을 확인했고, 경기 종목에 맞는 무승부 전적만 1회씩 반영됐다.

같은 API의 HTTP·DB 회귀 검사 47개가 통과했다. 클라이언트 로그에서 처리되지 않은 예외는 없었다. 실행 도구의 예외 검사는 기존 일부 예외명 목록에서 네임스페이스를 포함한 모든 `*Exception:` 행으로 확대해 `FormatException`, `IOException` 등도 탐지한다. 세 실행의 기존 로그에도 확대된 검사를 적용했다.

각 실행의 원본은 `Logs/LocalApiE2E/<실행 ID>/`에 있으며, 보고서·중간 차단 증빙·DB 대조 결과를 [LocalApiResultGuard.results.json](LocalApiResultGuard.results.json)에 함께 보관했다. 이 결과는 위 검증 범위에 적힌 물리 기기·API 공모·Photon 인증 연결의 남은 작업을 완료했다는 의미는 아니다.

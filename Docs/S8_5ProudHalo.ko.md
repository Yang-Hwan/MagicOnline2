# s8_5 뿌듯한 금빛 후광

싱글 3구·4구 연습과 멀티플레이가 공유하는 감정 어댑터에서 s8_5에 `PracticeProudHalo`를 연결한다. 기존 감정/미리보기 메시지가 전달한 수구 위치를 기준으로 재생한다. 점수·턴·공 물리·RPC 형식은 바꾸지 않는다.

- 0~0.65초: 금빛 입자가 수구 주변으로 모인다.
- 0.42~0.95초: 중심이 비워진 금빛 후광이 펼쳐진다. 광선은 초당 9도로 천천히 회전하고 약 1.2초, 1.95초에 두 번 밝아진다.
- 0.58초와 1.34초: 얇은 금빛 고리가 각각 확산된다.
- 0.95~1.3초: 작은 왕관이 수구 위로 올라온다. 별빛 다섯 개가 시간차를 두고 반짝인다.
- 2.2초부터: 금빛 입자가 위로 떠오른다. 후광·왕관은 2.35~3.35초에 걸쳐 옅어지고 모든 효과가 사라진 뒤 3.8초에 정리한다.

테이블과 공의 형태·위치를 변경하지 않는다. 화면에 투영한 Image를 ScreenSpaceOverlay Canvas(sortingOrder 32767)에 표시해 HUD·큐대 UI 위에 그린다. Image.raycastTarget=false, GraphicRaycaster 없음으로 입력을 가로채지 않는다. 다른 감정/새 샷/비활성화 시 숨기고 반복은 처음부터 재생한다. 처음 만든 이미지·스프라이트를 재사용하며 씬 종료 시 해제한다.

원래 MovStoryAni가 없는 감정 객체도 새 연출을 사용할 수 있도록 `PracticeSentimentActor.HasAnimation`으로 선택 그룹·재생·종료 판정을 통일했다. 기존 애니메이션이 있는 감정은 같은 경로를 유지한다.

에셋: `Assets/Resources/Gameplay/Sentiments/ProudHalo/PrideAtlas.png` (2×2 RGBA). 내장 image_gen으로 생성하고 중심 투명도를 편집한 최종 원본을 그대로 사용한다. 프롬프트: `Docs/S8_5ProudHalo.prompt.txt`.

리플레이: 기존 state-events의 Image 상태 및 런타임 Sprite 정의를 사용하며 새 아틀라스는 안정적인 에셋 ID로 등록한다. 새 저장 파일에서 수구 위치, 회전, 두 번의 밝기 변화, 고리 확산, 왕관·별빛, 소멸과 앞뒤 탐색을 복원한다. 영상 캡처나 경기 중 텍스처 복사를 추가하지 않는다.

검증 요청: `Logs/practice-demolition.request`, `Logs/multiplayer-sentiment-replay.request`. 원본 씬을 저장하지 않는 복사본/격리 씬에서 검사한다. 렌더 이미지: `Logs/Demolition/*-pride-*.png`, `Logs/MultiplayerSentiments/*-s8_5-*.png`.

최종 후광은 광선 중심/바깥 가장자리를 UI/SentimentHaloMask로 부드럽게 투명 처리한다. 원형 반경 기준으로 빛의 중심과 이미지 모서리를 제어해 수구와 테이블이 가려지거나 회전하는 사각 경계가 보이지 않게 한다. 왕관은 수구 바로 위로 위치를 맞췄다. 셰이더는 Resources와 리플레이 에셋 목록에 등록하고 재생 시 목록에서 로드한다.

2026-11-23 최종 검증: 싱글 256개, 멀티 저장·재생 120개, 공통 리플레이 25개(합계 401개)를 통과했다. 후광 투명 셰이더와 최종 에셋으로 재검증했으며 3구·4구 모두 s8_5 원본/재생 렌더의 평균 RGB 차이는 0이었다. 금빛 입자 집결, 고리 확산, 두 번의 밝기 증가, 왕관·별빛, 회전, 자연스러운 소멸, 중단·반복, 원래 테이블 복원을 확인했다. 새 아틀라스와 셰이더를 리플레이 에셋 ID로 등록했다. 실제 두 PC 접속 및 Windows 빌드는 실행하지 않았다. 새 저장 파일부터 새 연출이 기록된다.

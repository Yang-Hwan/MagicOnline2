# 새 3구·4구 대전 두 클라이언트 검증

2026-09-23. 테스트 전용 경로이며 일반 공개 전환은 아니다.

최신 성공 빌드: `Builds/PracticeMatchTest-20260926-142335`. 이 폴더 전체를 복사해서 사용한다. EXE/CMD만 복사하면 실행에 필요한 데이터와 DLL이 누락된다. 3구 기본 목표 2점과 시작·취소 보완을 포함하며 로컬 경로·입력·복구·결과 검사를 통과했다. 이 빌드의 실제 두 계정 재검증은 아직 하지 않았으며, 이전 빌드의 실기 결과는 아래에 항목별로 기록한다.

## 실행 준비

- 서로 다른 테스트 계정 두 개를 사용한다. 비밀번호를 문서나 로그에 기록하지 않는다.
- 두 실행본은 같은 프로젝트 버전/개발용 빌드를 사용한다. Photon 지역은 기존 kr 설정을 사용한다.
- Unity에서는 재생을 중지한 상태에서 `Tools > Magic Online > New Match Test > Enable In Editor`를 체크한 뒤 실행한다. 실행/연결 중에는 설정을 바꿀 수 없다.
- Windows에서는 개발용 빌드 폴더의 `Start-New-Match-Test.cmd`로 실행한다. 실행 인자는 `-practice-match-test`이다. EXE만 실행하면 기존 경기 경로를 사용하며, 일반 Release 빌드는 인자를 줘도 테스트 경로를 켜지 않는다.
- 빌드는 `Tools > Magic Online > New Match Test > Build Windows Test Player`로 생성한다. 최신 빌드 결과와 실행 파일 위치는 `Logs/practice-test-build.json`에 기록한다.
- 에디터 + Windows 빌드, 또는 Windows 빌드 두 개를 사용할 수 있다. 각각 다른 계정으로 로그인한다.

## 매칭과 경기

### 1분 종료·재대전 검증 옵션

개발용 `Start-Quick-Match-Test.cmd`는 기존 테스트 인자에 `-practice-match-quick`을 추가한다. 두 실행본 모두 이 옵션으로 시작해야 한다. 대기방에 `1분 종료 검증 · 친선`이 표시되며, `practice-match-test-9-quick` 버전/프로토콜로 일반 및 기존 테스트 방과 분리된다. 서버 차트 원본을 수정하지 않고 경기 설정 복사본의 제한시간만 1분으로 바꾼다. 3구 목표 2점·규칙·20초 차례 제한·종료 판정·재대전 승인 절차는 그대로다. Release 빌드와 일반 실행에서는 활성화되지 않는다.

타격 없이 기다리면 정상 시간 만료 경로로 무승부가 된다. 한쪽 재대전 요청만으로 시작하지 않는지, 양쪽 요청 후 새 matchId·선공 교대·0점·1분 시계로 다시 시작하는지 확인한다. 이는 시간 종료 검증이며 목표 점수 승리 검증을 대신하지 않는다.

1. 양쪽에서 대전 메뉴로 이동하고 같은 `3구테스트` 경기장을 선택한다. 대기방 제목의 `새 대전 테스트 (친선)` 표시를 확인한다.
2. 테스트 버전 `practice-match-test-9`끼리만 매칭된다. 한쪽만 테스트를 켜면 서로 만나지 않는다. 일반 버전 방의 설정 제안도 새 경기 전송기가 받지 않는다.
3. 기존 참가자 정보 교환/카운트다운 이후 기준 측이 설정을 제안한다. 양쪽 설정 확인과 TableSet07 로딩/준비 확인을 마쳐야 타격할 수 있다.
4. 지원 조건은 3구/4구, 목표점수 방식(FinishMission=0), 4구 쿠션 조건 0이다. 미지원 설정은 입장 실패로 처리한다. 로비의 기존 입장 조건은 유지한다.
5. 경기 후 `재대전 요청`을 양쪽에서 선택한다. 새 경기에서 점수 0, 공 초기 배치, 선공 교대, 새 경기 시간이 적용되는지 확인한다.
6. `마지막 샷 저장` 후 나가기를 눌러 메뉴로 돌아오고, 연습의 리플레이 메뉴에서 해당 슬롯을 재생한다. 파워·팔로스루·당점과 공 움직임을 확인한다.
7. 같은 절차를 `4구 테스트`에서 반복한다. 두 적구 후 상대 수구 접촉은 모든 공이 멈춘 뒤 감점이어야 한다.

## 연결 복구 전용 실행 및 최신 결과

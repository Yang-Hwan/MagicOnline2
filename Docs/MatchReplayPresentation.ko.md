# 멀티플레이 리플레이: 상태·연출 이벤트 기록

새로 저장하는 경기는 state-events-2 방식이다. 기존 v1~v3 공 기록과 v4 hud-mesh-1 파일도 읽는다. 바깥 파일은 기존 v4를 유지하고 화면 형식 식별자로 구분한다.

## 경기 중 기록

- 공 위치·회전과 실제 시간축은 최대 30Hz로 기록한다.
- HUD 활성화, 텍스트, 폰트, 색, 위치·크기·투명도, 이미지 ID 등 달라진 상태만 값 복사 형태로 메모리에 남긴다. JSON 직렬화·파일 압축은 경기 종료 후 처리한다. 코드로 생성되는 큐대·HUD 장식·발광·기술 불꽃은 원래 표시 코드에 필요한 수치와 시간만 기록한다.
- 월드 모델은 메시 에셋 ID와 변환값, 스킨 모델은 본 변환값을 기록한다. 파티클은 템플릿 ID·시각·시드와 CPU 시뮬레이션 상태·커스텀 스트림을 기록한다. 재생 시 입자를 다시 방출하지 않고 저장 상태를 적용하므로 하위 입자의 위치도 유지된다. 입자 데이터는 기록한 빌드와 같은 Unity 런타임 버전이 필요하다. 선은 제어점과 너비·색 설정을 기록한다.
- 일반 컴포넌트로 복원할 수 없는 소형 커스텀 Graphic은 변경 알림이 있을 때만 로컬 표시 데이터를 보완 기록한다. 경기 중 전체 화면 정점 투영·베이크·해시·압축을 수행하지 않는다.
- 이미지·모델은 GUID와 서브에셋 ID를 참조한다. 빌드 전 MatchReplayAssetBuilder가 ID 목록과 안전한 파티클 템플릿을 생성한다. 에셋 참조는 파일별로 나누어 필요할 때 로드하며 전체 에셋을 한꺼번에 로드하지 않는다.
- 다운로드한 아바타와 동적 폰트 이미지 등 런타임 에셋은 참조만 보관하고 경기 종료 후 한 번 변환한다. PNG 변환과 파일 압축은 경기 진행 중 수행하지 않는다.
- 최초 등록 후에는 계층 변경 알림으로 새로 생긴 부분만 검색한다. 매 기록 시 장면 전체를 다시 순회하지 않는다. 표시 컴포넌트가 없는 UI 중간 부모도 RectTransform으로 보존하며 Canvas와 Graphic이 함께 붙은 오브젝트도 복원한다.
- Canvas·렌더러의 원래 정렬 순서와 정렬 레이어를 유지한다. 원형 방향 조작부처럼 SpriteRenderer로 표시하는 HUD도 기록한다. 커스텀 UI의 텍스처는 표시별로 적용하며 공유 재질의 텍스처를 덮어쓰지 않는다.
- 프리미엄 큐의 실행 중 생성 메시(본체·움직이는 효과)는 에셋 ID로 조회하지 않는다. 디자인·원본 크기·충전·타격 시각·표시 시각·시점 방향만 기록하고 표시 전용 컴포넌트에서 복원한다. 천둥·성운·불꽃 3종의 원본/재생 메시와 색상 일치 검사를 포함한다.
- Unity가 무시하는 내장 시간 상수의 재질 덮어쓰기 호출은 하지 않는다. 큐·HUD의 코드 연출은 기록된 시각과 상태를 사용한다.
- 마지막 승패·점수·서버 확정 결과, 결과 화면의 표시 변화도 함께 기록한다. 종료 후 최대 8초간 기록하며 저장 창을 열면 그 직전에 확정한다. 저장 창은 포함하지 않는다.

## 재생

재생기는 표시용 컴포넌트만 만든다. 버튼·점수 판정·재화 지급·네트워크 호출·게임플레이 스크립트를 실행하지 않는다. 원래 HUD와 월드 효과를 숨기고 저장된 상태를 복원하며 닫으면 원래 표시를 복구한다.

일시정지·배속은 같은 시간축을 사용한다. 뒤로 이동하면 상태를 초기화하고 지정 시점까지 표시 이벤트만 적용한다. 파티클은 저장한 상태를 직접 복원하며 실제 보상을 재실행하지 않는다.

기록 시 사용한 에셋 ID가 있는 빌드가 필요하다. 이후 에셋이 삭제·교체되면 이전 리플레이 호환성도 검증해야 한다. 음향은 이 화면 리플레이 형식의 기록 대상이 아니다.

## 검증·성능 측정

- Logs/replay-state-validation.request에 validate를 쓰면 에셋 ID 생성과 상태 기록·파일 왕복·승패·되감기·표시 복원 검증을 실행한다. build는 Build/Windows/MagicOnline2.exe 개발 빌드까지 만든다.
- 결과: Logs/replay-state-validation.json.
- 클라이언트의 -replay-performance 옵션 뒤에 JSON 경로를 지정하면 경기 중 프레임 시간과 기록 작업 시간을 측정한다. -replay-recording-off를 추가한 동일 경기와 비교한다.
- Server/GameApi/Run-ClientE2E.ps1 -Mode public은 두 로컬 클라이언트의 일반 대기실→Pavilion→결과 경로, 저장 파일 작성·재생 구간 이동을 검사한다. -ReplayBaseline은 기록하지 않는 비교 실행이다. 실행 폴더의 성능 JSON, 리플레이 검증 JSON, 원본/재생 결과 PNG를 확인한다.
- 숨김 테스트 창은 화면 출력이 검게 캡처될 수 있으므로 결과 이미지 검증은 실제 카메라와 UI를 별도 렌더 타깃에 렌더링한다. 결과 화면 이미지의 평균 RGB 차이를 검사하며, 파티클 위치·색·크기와 UI 부모 앵커는 별도 검증한다. 한 PC의 두 클라이언트 측정이며 두 실제 PC 사이의 네트워크 품질이나 모든 연출 조합을 검증한 것은 아니다.
- 120,000프레임, 표시 영역 256MiB 상한을 유지한다. 기록 오류는 시합 진행을 중단하지 않으며 불완전한 리플레이를 정상 저장하지 않는다.

## 2026-11-21 실측

- Windows 개발 빌드, 같은 PC의 숨김 클라이언트 두 개, 각각 960×540 조건이다. 화면 비교는 별도 렌더 타깃에서 수행했다. 전체 화면 GPU 성능이나 두 실제 PC 간 지연을 뜻하는 수치가 아니다.
- 일반 대기실→Pavilion→결과→저장→재생·되감기: 양쪽 통과. 원본/재생 결과 화면 평균 RGB 차이 A 0.078%, B 0.072%로 1% 기준을 통과했다. 검증 폴더: Logs/LocalApiE2E/public-4397babedf2a41f28dbc68f6bc32618f.
- 해당 실행의 기록 작업은 평균 약 3ms였다. 약 79초 경기의 저장 파일은 약 1.10MB였다. 최초 에셋·계층 등록의 단발 비용은 별도이며 테스트 과정에서 약 0.3~0.8초의 진입 지연이 관찰됐다.
- TableSet07 실제 물리 샷과 정상 종료 경기의 저장·재생·무승부 결과 보존도 양쪽에서 확인했다. 풀링 시 Coin_LightUp이 CoinLightUp으로 바뀌는 경우도 같은 템플릿을 연결한다.
- 재대결 테스트의 두 번째 라운드는 방 이탈에 의한 항복 정산 경로다. 결과 화면에 도달한 정상 완료 경기에서만 리플레이 저장을 검사하며, 방 이탈 경기를 정상 완료 저장으로 취급하지 않는다.
- 최종 Windows 빌드는 19개 상태·파일·표시 회귀 검사를 통과했다. 런타임 소스 471개를 플레이어 PDB의 SHA-256과 대조해 모두 일치했다. 최종 실제 샷·정상 경기 저장·재생·재대결·항복 정산은 Logs/LocalApiE2E/rematch-fdea0165c0594110b3b6404f5a659ea6에서 양쪽 PASS를 확인했다. 경기 기록 평균 비용은 약 3~3.4ms였다.


## 2026-11-22 재대결 UI 및 저장 용량 수정

- 큐대 UI에 경기 진행 여부 콜백을 추가했다. 종료·재대결에서는 금속 패널/상대 턴 덮개/기존 게이지를 모두 숨기고 다음 경기에서 정상 복구한다. 기존 Pavilion과 PracticeMatchAdapter 경로에 모두 연결했다.
- 표시 저장 포맷 버전 2는 이벤트 문자열을 같은 부품의 직전 이벤트와 비교해 공통 앞·뒤 구간을 참조하고 바뀐 구간만 기록한다. 표시 내용과 순서는 생략하지 않는다. 기존 버전 1 읽기도 유지한다.
- 압축 전 표시 데이터 256MiB 한도를 높이지 않았다. 이전 방식은 반복 JSON 전체 길이로 한도를 판단했다. 새 방식은 차분 기록 크기로 판정한다. 읽기 시 이전 이벤트 인덱스/문자 범위를 검사하고 복원 문자열 총량도 제한한다.
- 저장 시 InvalidDataException도 처리하여 실패 사유를 보존한다. 슬롯 선택 창에 실패 안내를 표시하고 로그에 상세 사유를 남긴다. 기존 슬롯은 임시 파일 작성 성공 전 덮어쓰지 않는다.
- 저장 제목 입력란의 TextViewport를 명시하고 활성화 전에 구성한다.
- 검증: 별도 Unity에서 원래 286MiB를 넘는 반복 이벤트 10,000개가 39,691바이트로 저장되고 완전히 동일하게 복원됨. 한글/이모지, 버전 1 읽기, 잘못된 차분 참조 거부, 자기 턴/상대 턴/종료/디자인 전환/다음 경기 UI 검사 통과. 실제 두 플레이어의 전체 경기 저장 재현 검증은 별도다.


### 2026-11-22: 리플레이 코인 배율 및 메시지 선택 목록

- `CoinAni/Root`는 Local 스케일 모드와 0.06 배율을 사용한다. 기존 재생기는 기록된 Transform 아래에 배율 1인 파티클 자식을 생성해서 약 16.7배 크게 표시했다. 파티클 자체에 기록된 Transform을 적용하도록 변경했다. 기존 state-events 저장 파일도 재생 시 수정된다.
- 개인 메시지 선택 목록(`EquippedChatMenu`)과 전용 암전 배경은 기록에서 제외한다. 기존 state-events 파일에서는 목록 하위 노드와 같은 부모의 구형 `Modal Backdrop`도 숨긴다. 전송된 `SelfChat`/`OtherChat` 말풍선은 유지한다.
- 회귀 검증 메뉴: Tools > Gameplay > Validate Replay Coins and Message Menu. 배율, 시간 이동, 기존 목록 숨김, 신규 기록 제외 및 말풍선 유지 확인.
- 검증 결과: 게임 C# 컴파일 오류 0개. 별도 Unity 프로젝트에서 수정된 실제 Assembly-CSharp를 로드하여 8개 회귀 검사 통과 (`Logs/ReplayEffectValidationProject/Logs/replay-coin-menu-result.txt`). 실제 저장 경기의 화면 대조 및 실행 파일 재빌드는 이번 검증에 포함하지 않았다.


### 2026-11-22: 소형 저장 형식과 이닝 이동

- 신규 전체 시합은 파일 버전 5, 화면 기록 버전 3을 사용한다. 기존 파일 버전 1~4 및 화면 기록 버전 1~2는 계속 읽는다. 개별 샷 저장은 기존 버전 3을 유지한다.
- 공 위치·회전·속도·각속도·프레임 시각은 부동소수점 비트를 XOR 차분한 뒤 gzip으로 무손실 압축한다. 프레임을 버리거나 물리를 다시 계산하지 않는다. 전체 시합에서 사용하지 않는 큐 상태 반복 저장도 제거한다.
- 화면 상태와 선/메시 좌표는 JSON 문자열 대신 바이너리와 차분으로 저장한다. 화면에 그리는 선만 최대 0.0001 좌표 단위 오차 이내에서 불필요한 중간 점을 제거하며 끝점과 꺾임을 보존한다. 이 처리는 공의 실제 운동 기록에 영향을 주지 않는다.
- 자체 방출하는 장식 파티클은 종류·변환·시드·방출 상태·시계 앵커로 재생한다. 충돌/트리거/서브 이미터/사용자 좌표계 등 재생 의존성이 있는 효과는 기존 입자 버퍼 방식을 유지한다. 장식 입자의 세부 배치는 원본과 완전히 일치하지 않을 수 있다. 방출이 끝나도 살아 있는 입자를 유지하고 되감기 시 복원한다.
- HUD 타이머/빛 변화는 이벤트 앵커에서 계산한다. 득점과 턴, 게이지 상태 변경 및 예상 시계에서 벗어난 변경은 다시 기록한다.
- 플레이 중 `Inning Score UI`의 열기·닫기와 스크롤은 기록하지 않는다. `inning-score` 이벤트에는 기록 프레임·각 선수의 방문 차수·누적 이닝 점수·선수명을 저장한다.
- 리플레이에서 기존 위치의 이닝 점수표를 열고 선수/이닝 셀을 누르면 해당 턴 시작으로 이동한 뒤 일시정지한다. 미래/과거 모두 이동 가능하며, 진행하지 않은 셀은 클릭할 수 없다. 총점과 각 이닝 점수는 경기 전체 기록을 보여 주고 현재 재생 턴을 강조한다. 도구창을 드래그하거나 일시정지해도 점수표 위치는 화면에 고정한다.
- 기존 state-events 저장 파일은 HUD의 턴과 점수 이벤트로 이동 인덱스를 복원한다. 명시적인 턴 시각이 없는 구형 파일은 HUD가 바뀐 프레임을 사용한다. HUD 이벤트도 없는 구형 파일은 이닝 이동을 제공하지 않는다.
- 용량 측정: 기존 슬롯 15의 934.79초(15분 35초), 26,844,322바이트 기록을 복사본에서 새 방식으로 재인코딩하는 검증에서 공 936,215바이트 + 화면 3,670,293바이트, 헤더 포함 약 4,606,565바이트(약 83% 감소). 28개 턴 구간 유지. 사용자 저장 원본은 변경하지 않았다. 이 값은 기존 기록의 효과/화면을 재인코딩한 표본이며 실제 신규 녹화 크기는 효과와 샷 횟수에 따라 달라진다. 20분 3MB의 고정 용량은 보장하지 않는다.
- 검증 메뉴: `Tools > Gameplay > Validate Compact Match Replay`. 20분 공 기록 무손실 왕복, 손상 파일 거부, 바이너리 좌표, 선 오차 한계, 실제 버전 5 로더, 상대 3이닝/자신 2이닝 클릭, HUD 시계 및 코인 효과 되감기 검사. 실제 두 클라이언트의 신규 경기 전체를 다시 녹화하는 실사용 검증과 EXE 재빌드는 별도다.
- 최종 검증 결과: C# 컴파일 오류 0개, `compact-runtime-check.log`의 Unity 검사 22개 통과. 용량 재인코딩을 포함한 이전 통합 실행(`compact-check4.log`)도 22개 통과.


### 2026-11-22 큐대 계층과 리플레이 조작 UI 보완

- 큐대를 샷 준비 위치/샷 종료 위치로 옮길 때 Transform 부모 변경을 `visual-parent` 이벤트로 기록한다. 기존 v5/v3 파일 형식은 유지하며 역방향 탐색 시 최초 계층을 복원하고 이벤트를 재적용한다.
- 렌더러의 `forceRenderingOff`도 반영한다. 공 둘레 링과 두께 확인용 ChkBall은 연습/멀티플레이에서 숨기며, 기존 state-events 리플레이에서도 제외한다. 확대 당점창 PointBig 및 해당 BlindBack도 기록/재생에서 제외하고 작은 당점 표시는 유지한다.
- 이닝 탐색 UI는 재생 도구 패널의 자식이 아닌 독립 ScreenSpaceOverlay Canvas(32002)와 GraphicRaycaster를 사용한다. 라이브 UI 숨김 대상에서도 명시적으로 제외한다.
- 사용자 기본 슬롯 16을 읽어 7이닝, 14턴, inning-score 이벤트 23개가 존재함을 확인했다.
- 과거 파일에는 부모 변경 정보가 없으므로 큐대의 모든 자세를 정확하게 복원할 수는 없다. 계층 기록 수정은 새로 녹화하는 시합부터 적용된다. 기존 파일의 공 궤적/이닝 정보는 그대로 유지한다.
- ReplayHierarchyValidation: 압축 저장 후 부모 변경/복귀/역방향 탐색, 렌더 숨김, 기존 오버레이 제외, 독립 점수표와 클릭 이벤트/레이캐스트 등록 검사. 배치 에디터는 Game View가 렌더되지 않아 native depth=-1일 때 실제 마우스 클릭 대신 Graphic 등록 및 필터를 검사한다.

- 시합 녹화에서 `BtnMatchEnd`(나가기)와 `PlayerInformation`(선수정보 전체 팝업/암전)을 제외한다. 실제 플레이 중 버튼과 선수정보 열람은 유지한다. 기존 state-events 저장 파일도 재생 시 해당 노드와 자식들을 숨긴다. 파일 원본을 다시 쓰거나 아바타 자체를 제외하지는 않는다.


### 시합 리플레이 전용 조작 UI

- 좌측 상단 `나감`은 녹화된 BtnMatchEnd와 별개로 항상 활성화된다. 리플레이 정리 후 PracticeSceneFlow.ReturnToMenu를 통해 메인 메뉴로 돌아간다.
- 우측 당점 표시 아래 `작동`, `목록`, `점프`는 독립 토글이다. 처음 진입 시 작동만 켜지고 나머지는 꺼진다. 슬롯 교체 시 사용자 토글 상태를 유지한다.
- 작동 UI: 하단 한 줄에 진행률 슬라이더, 속도 감소/표시/증가, 재생·일시정지, 다음, 처음 버튼을 배치한다.
- 목록 UI: 우측 버튼 왼쪽에 기존 폴더, 제목/재생정보, 슬롯을 표시한다. 기존 드래그 핸들은 목록 패널만 이동하며 작동/나감/토글은 움직이지 않는다. 폴더 추가·삭제 창도 목록 패널 내부에서 열린다.
- 점프 UI: 기존 이닝 점수표를 상단 HUD 위로 배치하고 기존 점수표 아이콘은 숨긴다. 점수 선택 시 해당 턴으로 이동한 뒤 일시정지한다. 이닝 데이터가 없으면 점프 버튼은 비활성화한다.
- 전체 컨트롤 루트는 투명하고 비레이캐스트 상태이며, 모든 선택 패널을 닫아도 나감과 토글 버튼은 유지된다. 연습 리플레이와 시합 저장 패널은 기존 배치를 유지한다.

- 리플레이 전용 디자인: ReplayChromeGraphic의 해상도 독립 둥근 모서리, 차콜 그라데이션, 금속 테두리/상단 반사광을 사용한다. 버튼 활성은 에메랄드, 선택 슬롯은 앰버로 표시하고 슬롯/폴더 상태 갱신 때도 유지한다. 하단 진행 표시는 현재/전체 시간(mm:ss)이며 점프 점수표는 900 기준 단위 이내의 상단 중앙 패널이다. 목록은 0.82 배율로 표시하며 드래그/해상도 변경에서도 동일 배율 상한을 지킨다.


### 수구 실제 궤적과 경기장 외형

- 녹화/기존 state-events 재생에서 SupportLines 하위 가이드라인과 라이브 이동선은 제외한다. 샷 이벤트의 seat와 저장된 공 위치만으로 수구 궤적을 재생 시 재구성한다. 궤적 정점 데이터를 중복 저장하지 않는다.
- 다음 shot 이벤트에서 이전 궤적을 비우고 새 수구로 전환한다. 앞/뒤 건너뛰기는 해당 샷 시작부터 현재 프레임까지 재구성한다. 정지 중 중복점을 제외하고 런타임 최대 4096점을 넘으면 표시용 경로만 간소화한다. 원본 공 위치/운동 데이터는 바꾸지 않는다.
- TableBg의 실제 스프라이트에서 ArenaTableSkins의 리소스 이름을 식별해 arena-table 이벤트로 기록한다. 텍스처 픽셀을 파일에 넣지 않고 내장 리소스를 재사용한다. 7번 경기장의 BlackGold/Titanium 변형도 실제 선택된 스킨 이름을 저장한다.
- 재생/역방향 탐색 때 해당 시점의 스킨을 적용하고 종료 시 원래 테이블을 복원한다. 과거 파일에 경기장 정보가 없으면 기본 테이블을 유지하며, shot 이벤트가 없는 파일은 수구를 임의로 추정하지 않는다.

## 결과 화면에서 녹화 종료

승리·패배·무승부가 실제 표시된 시점부터 3초까지 기록한다. 기존의 경기 완료 이벤트 기준 8초 종료는 제거하여 결과 확인 대기나 마지막 기술명 연출 때문에 결과가 잘리지 않게 한다. 재대결 전환 직전에는 결과 화면이 보이는 상태에서 Seal하며, 재대결 화면 OnEnable에서도 새 프레임 캡처 없이 중단한다. 이후 슬롯 저장은 종료된 기록을 사용한다. 기존 저장 파일의 재대결 화면은 소급 삭제하지 않는다.

### 리플레이 컨트롤 Canvas 복구

리플레이 초기화 전에 `EnsureReplayControlCanvas`가 Canvas 및 GraphicRaycaster를 확보한다. Unity 컴포넌트의 누락/삭제 참조는 일반 C# `??`가 아니라 Unity의 유효성 검사(`if (!component)`)로 검사한다. 슬롯 반복 선택 시 기존 Canvas를 재사용하며, 누락되었거나 비활성화된 경우 생성·활성화한다. 표시 객체를 구성하기 전에 검사하여 Canvas 오류 때문에 리플레이가 부분 초기화 상태로 남지 않게 한다.

### 리플레이 UI 효과의 CanvasRenderer

상태 복원 시 2D UI 그래픽(텍스트·이미지·사용자 정의 그래픽·게이지·광택·불꽃·HUD)은 Graphic 컴포넌트보다 먼저 CanvasRenderer를 생성한다. 상태 색상 적용에도 Unity 유효성 검사를 사용하며, MeshRenderer를 사용하는 월드 TextMeshPro는 CanvasRenderer 색상 적용에서 제외한다. 실제 플레이의 Impact embers에도 CanvasRenderer 의존성을 명시한다.

# 관리자 회원 삭제

작성일: 2026-11-13

## 사용 방법

최고 관리자(Owner)로 관리자 사이트의 `회원 관리`에 접속한다.

- 한 명 삭제: 목록의 `삭제` 또는 회원 상세의 `회원 삭제 확인`을 누른다.
- 여러 명 삭제: 체크박스로 선택하거나 `이 페이지 전체 선택`을 누르고 `선택 회원 삭제 확인`으로 이동한다. 검색·필터를 유지하며 현재 페이지의 최대 30명만 선택한다.
- 확인 화면에서 로그인 ID·닉네임·UUID와 진행 상태를 검토한다.
- 삭제 사유와 확인 문구 `삭제`를 입력하고 최종 삭제 버튼을 누른다.

Operator와 Viewer에게 삭제 기능을 허용하지 않는다. GET과 삭제 미리보기 POST는 회원 상태를 변경하지 않는다. 최종 POST에는 기본 Razor antiforgery 검증을 적용한다. JavaScript를 사용하지 않으므로 기존 script-src 'none' 정책을 유지한다.

## 삭제 의미

연결된 대전·정산·재화 기록을 훼손하지 않기 위해 논리 삭제를 사용한다.

- users.deleted_at을 기록하고 disabled=true로 바꾼다.
- 회원 목록, 정상/제한 필터, 회원 수 통계 및 회원 상세에서 제외한다.
- 기존 인증 세션을 모두 폐기하며 로그인·토큰 갱신·기존 토큰 사용을 차단한다.
- 로그인용 고유 키를 별도의 삭제 키로 변경해 같은 로그인 ID로 새 계정을 가입할 수 있게 한다. 재가입 계정은 다른 UUID이며 이전 지갑·보유 상품을 이어받지 않는다.
- 원래 로그인 ID·닉네임·UUID, 잔액·원장·구매·보유·대전·정산 데이터는 기록 연결을 위해 보존한다. 물리 삭제나 개인정보 완전 삭제 기능은 아니다.
- 친구 목록과 요청에서 제외하고 접속 상태를 제거하며 관련 친구 도전을 닫는다.
- 관리자 감사 기록에 회원별로 대상, 변경 전 이름, 삭제 상태와 사유를 남긴다.
- 이 기능의 복원 UI는 제공하지 않는다.

선택한 회원 중 서버에 등록/진행/미정산 상태인 경기가 하나라도 있으면 전체 삭제를 거부한다. 해당 경기를 종료한 뒤 다시 선택해야 한다. 회원 UUID와 확인한 로그인 ID가 달라졌거나 로그인 작업이 세션을 잠그고 있으면 충돌로 안내하고 다시 확인하도록 한다.

## 동시 처리와 이력 보호

사용자 지갑과 사용자 행을 일관된 순서로 잠그고, 계정 변경·세션 폐기·친구 상태 정리·감사 기록을 하나의 DB 트랜잭션으로 처리한다. 중간 실패 시 전부 취소하며, 같은 회원을 반복 삭제해도 추가 감사 기록을 만들지 않는다.

새 경기 등록도 사용자 행을 공유 잠금으로 검사해 삭제와 동시에 새 경기가 생성되는 경합을 막는다. 삭제 회원의 관리자 닉네임·재화 수정과 공개 프로필 조회도 거부한다. 다른 회원의 지갑이나 경기·정산 이력은 삭제하지 않는다.

012_member_deletion.sql은 users.deleted_at과 현재 회원 조회용 인덱스를 추가한다. 기존 테이블·외래 키를 제거하거나 CASCADE 삭제를 추가하지 않는다.

## 검증 결과

- 서버 및 Razor 페이지 빌드: 경고 0, 오류 0.
- 실제 PostgreSQL 임시 스키마에서 삭제 검사 33개 통과: 권한, 대상·확인 문구·사유 검증, 일괄 제한, 미종료 경기, 동시 인증·삭제, 실패 시 롤백, 중복 제출, 세션 폐기, 친구 상태, 회원 조회 제외, 지갑·구매·원장 보존, ID 재사용 및 삭제 회원의 새 경기 등록 차단.
- 기존 관리자 재화 조정 검사 9개 및 경기 복구·정산 검사 32개 통과.
- 실제 실행 중인 관리자 사이트에서 검색된 페이지 전체 선택, 미리보기, 단일·일괄 삭제, 잘못된 확인 문구, CSRF 누락, 중복 제출, 삭제 후 목록·상세 제외와 로그인·access·refresh 차단을 확인했다.
- 실제 API에서 같은 로그인 ID로 새 UUID의 계정을 가입할 수 있음을 확인했다.
- HTTP 검증에서 직접 생성한 테스트 회원 13개를 모두 이 삭제 흐름으로 정리했다. 기존의 일반 회원을 임의로 삭제하지 않았다.
- API와 관리자 사이트는 새 코드로 재실행하고 정상 응답을 확인했다.

```powershell
dotnet build Server/MemberDelete.Tests/MemberDelete.Tests.csproj --output "$env:TEMP/MagicOnline2-MemberDeleteTests"
dotnet "$env:TEMP/MagicOnline2-MemberDeleteTests/MemberDelete.Tests.dll"
```

## 삭제 확인 버튼 회귀 수정

여러 회원 선택 후 확인 페이지의 URL에 handler=Preview가 남았고, action을 지정하지 않은 최종 폼도 그 주소로 제출돼 미리보기를 반복하는 문제가 있었다. 최종 폼에 MemberDelete 페이지와 Delete 핸들러를 명시해 실제 삭제 처리로 전달하도록 수정했다.

기존 HTTP 검사가 최종 제출 주소를 직접 지정해 이 문제를 발견하지 못했으므로, 렌더링된 폼의 action과 hidden 입력만 읽어 실제 브라우저와 같은 흐름으로 제출하는 검사를 추가했다. 다중 선택 진입·개별 진입, 잘못된 확인 문구, 오류 후 재시도, 실제 삭제·리디렉션 및 중복 제출을 포함한 14개 검사를 통과했다. 직접 생성한 검증용 계정만 사용하고 정리한다.

```powershell
dotnet build Server/MemberDelete.Tests/MemberDelete.Tests.csproj --output "$env:TEMP/MagicOnline2-MemberDeleteButtonTests"
dotnet "$env:TEMP/MagicOnline2-MemberDeleteButtonTests/MemberDelete.Tests.dll" --http http://127.0.0.1:5082 http://127.0.0.1:5080
```

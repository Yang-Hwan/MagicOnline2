# Unity 상점 상품 조회 연결

작성일: 2026-11-12

## 적용 범위

관리자 사이트의 상점 상품을 Unity 하단 메뉴의 상점에서 조회한다. 보석으로 큐대·캐릭터·메시지를 구매하고 영구 보유할 수 있다. 장착 선택은 [보유장비 연결 문서](OwnedEquipmentIntegration.ko.md)를 참고한다. 현금 결제는 포함하지 않는다.

## 조회 계약

- `GET /api/shop/products`: 게임 계정 인증 필요. 기존 GameApiClient의 토큰 및 갱신 처리를 사용한다.
- 응답은 `Products` 배열을 가진 객체이며 Unity의 `ShopCatalogData`로 읽는다.
- `visible=true`이고 현재 서버 시각이 판매 기간에 해당하는 상품만 반환한다. 시작·종료가 없는 항목은 해당 경계를 제한하지 않는다.
- 정렬 순서와 ID 순서로 반환한다.
- 판매 중지 상품도 표시하되 `Purchasable=false`를 반환한다. 비공개와 판매 중지는 별도 설정이다.
- 보석 팩 수량·추가 수량, 큐대 능력치, 캐릭터 감정별 리소스, 순서가 있는 메시지 목록을 함께 제공한다.
- 현금 가격과 실제 결제 상품 연결은 아직 제공하지 않는다. 임의의 현금 가격을 표시하지 않는다.

## Unity 화면

- 전체 / 보석 / 큐대 / 캐릭터 / 메시지의 다섯 탭을 제공한다.
- 세 상품씩 표시하고 이전·다음으로 이동한다.
- 상품을 누르면 상세 정보가 열린다.
- 상점 진입, 종류 변경, 새로고침 시 서버에서 다시 조회한다.
- 로딩·로그인 필요·빈 목록·연결 실패를 구분해서 표시한다.
- 대표 이미지가 없으면 큐대 리소스 또는 캐릭터 기본 감정 리소스를 사용한다.
- 이미지 경로는 Resources의 Texture2D 키 또는 HTTPS 이미지 URL을 지원한다. 개발용 루프백 HTTP도 허용한다.
- 누락된 이미지나 다운로드 실패는 '이미지 준비 중'으로 표시한다. 프리팹·AssetBundle·Addressables의 로딩은 포함하지 않는다.
- 화면을 벗어난 뒤 도착한 상품 응답은 버린다. 다운로드 텍스처는 카드 재구성 및 화면 파괴 시 정리한다.

## 확인 방법

1. API 서버를 최신 코드로 실행한다.
2. Unity에서 로그인 후 하단 상점 메뉴를 연다.
3. 종류별 탭과 상품 상세를 확인한다.
4. 관리자 사이트에서 상품을 수정한 후 Unity 상점의 새로고침을 누른다.

Unity 에디터 메뉴 `Tools > Local Game API > Verify shop catalog`에서 실제 UnityWebRequest와 JsonUtility를 통한 조회 검사를 실행할 수 있다. 로그인이 없으면 로컬 검사용 게임 계정을 생성하고 검사 후 로그아웃한다. 응답 확인 파일은 `UserSettings/ShopCatalogSmokeTest.json`에 기록한다.

관리자가 등록한 테스트 상품은 종류별 3개, 총 12개다. 이미지 경로는 임시 값이고 판매는 중지 상태이므로 이미지 대체 문구와 판매 중지 표시가 정상이다.

## 검증 결과

- 서버 빌드: 경고 0, 오류 0.
- 실행 중인 API: 미인증 요청 거부, DB의 공개·판매 기간 조건 및 정렬 순서와 응답 일치 확인.
- 테스트 상품 12개, 감정 정보 27개, 메시지 15개가 응답에 포함됨을 확인.
- Unity 6000.5.7f1 배치 실행: 컴파일 및 UnityWebRequest / JsonUtility 조회 통과. 당시 전체 공개 상품 16개를 읽음.
- Unity UI 객체 검사: 다섯 탭의 분류, 페이지 이동, 상품 상세 창, 빈 목록 처리 통과.
- 배치 검사는 그래픽 장치를 사용하지 않았으므로 실제 화면의 시각적 배치와 원격 이미지 다운로드 성공 여부는 검증 범위에 포함하지 않는다.
- API 서버는 최신 코드로 다시 실행한 상태다.

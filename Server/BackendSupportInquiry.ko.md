# 기존 게임 정보와 펑션으로 1:1 경기 정산 가능한지 확인하는 문의 초안

이 문서는 문의 초안이며 외부로 전송하지 않았다. 인증키·사용자 정보·실제 잔액을 첨부하지 않는다.

Unity 게임에서 뒤끝 베이스 GameData를 사용하고 있으며, 뒤끝 펑션(.NET 8)과 새 데이터베이스를 활성화했습니다. 별도 외부 서버 없이 1:1 경기 코인 정산을 펑션에서 처리하려고 합니다.

공식 펑션 1.0.2 템플릿 Backend.dll에는 Database API가 확인되지 않았고, com.backnd.database 0.0.18 공개 Client/DatabaseExecutor는 UnityEngine/UnityWebRequest와 로그인 사용자 초기화에 의존합니다.

다음을 확인 부탁드립니다.

2026-02-24 커뮤니티 답변(https://community.thebackend.io/t/topic/11164)에서 새 데이터베이스의 펑션 사용 미지원을 확인했습니다. 우선 **기존 베이스 GameData와 펑션만으로 아래 요구를 충족하는 공식 방법**이 있는지 답변 부탁드립니다.

- 펑션에서 두 참가자 UserMain과 상대방 Private UserMatchHistory를 수정할 수 있는 서버 전용 권한이 있나요? 없다면 서버 정산 기록을 보관하는 공식 권장 구조는 무엇인가요?
- GameData TransactionWriteV2의 Where 조건(상태/버전/잔액)이 실제 쓰기 시점에 원자적으로 검사되나요, 아니면 행을 조회하는 용도로만 쓰이나요? 동시 두 요청이 같은 이전 버전을 조회한 뒤 둘 다 성공할 수 있는지 확인 부탁드립니다.
- MatchId의 영구 고유성과 조건부 실패 시 전체 롤백을 이용해 경기당 단 한 번의 지급을 보장하는 공식 예제가 있나요?
- 전적·코인 필드의 클라이언트 직접 쓰기를 막고 펑션만 쓰도록 하는 권한 설정은 무엇인가요?

아래는 새 데이터베이스 지원이 이후 변경되었다면 확인하고 싶은 항목입니다.

1. .NET 8 뒤끝 펑션에서 새 데이터베이스에 접근하는 공식 SDK/API와 예제는 무엇인가요?
2. ClientAccess=false인 서버 전용 테이블을 펑션에서 읽고 쓰는 인증·권한 설정 방법은 무엇인가요? SDK의 로그인 사용자 권한과 다른 서버 권한을 지원하나요?
3. 트랜잭션에서 두 사용자 잔액·전적, 경기 상태, 고유 MatchId 정산 원장을 함께 쓰고 싶습니다. 중복 PrimaryKey Insert 실패 시 전체 롤백이 보장되나요?
4. 잔액 조건 또는 Version 조건의 Update가 0행일 때 전체 트랜잭션을 실패시킬 수 있나요? 가능하다면 공식 예제를 부탁드립니다. 커밋 후 TotalAffectedRows 검사로는 부분 변경을 되돌릴 수 없습니다.
5. 공용 기본 키 한 건에 대해 동시 요청의 compare-and-swap 또는 행 잠금/격리를 지원하나요?
6. 기존 베이스 GameData와 새 데이터베이스를 같은 트랜잭션에 포함할 수 있나요? 미지원이면 코인·전적 원본을 새 데이터베이스로 이전할 계획입니다.
7. 공개 문서는 트랜잭션 최대 10개, npm 0.0.18 코드에서는 100개로 되어 있습니다. 현재 서버의 실제 제한은 무엇인가요?

목표 정책은 경기 시작 시 양쪽 입장료 차감, 승자에게 합계 지급, 무승부 각자 반환이며 재전송·동시 요청에도 경기당 한 번만 반영하는 것입니다.

## 추가 확인 요청 초안 — 2026-10-09 실제 검사

Function SDK에서 호출자 A 인증으로 공개 GameData의 A/B 행을 GetV2 조회하고 SetUpdateV2로 양쪽 갱신하는 것은 성공했습니다. 하지만 TransactionValue.SetUpdate의 owner_inDate·RunId·Slot·Version 조건으로 A 자신의 두 행을 갱신하는 것은 204, B 행을 같은 방식으로 갱신하는 것은 404 NotFoundException입니다. 두 지갑과 경기 상태를 버전 조건으로 함께 갱신할 공식 서버 권한 API가 있나요? SetUpdateV2에 조건식을 제공하거나 조건 검사와 갱신을 원자적으로 묶는 방법이 있는지도 확인이 필요합니다. 문의는 전송하지 않았습니다.
